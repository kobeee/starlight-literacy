# 2026-05-01 Mobile H5 第一关点击热区修复

## 背景

用户在 in-app browser 打开 Mobile H5 后反馈：点击第一关没反应。

当时页面地址：

```text
http://127.0.0.1:4173/src/clients/mobile-h5/
```

这次问题发生在 P01 学习地图。P01 是 `390×1800` 长轴画卷，依赖 pointer 事件做自定义拖动；第一关同时有圆形节点和旁边的文字标签。

## 问题定位

代码层面，第一关圆形节点本身已经有：

```html
data-action="open-unit"
```

用 in-app browser 的可访问按钮直接点击 `开始第 1 组` 可以进入 P02，说明 `handleClick()` 和 `open-unit` 路由逻辑是通的。

实际可感知的“点了没反应”主要来自两个交互细节：

1. 第一关旁边的文字标签原来是普通 `div`，并且 `.journey-label` 设置了 `pointer-events: none`。用户如果点文字区，会看起来像点了第一关，但不会触发任何动作。
2. 首页地图的拖动逻辑在任意 `[data-home-map]` 区域 `pointerdown` 都会启动。落在按钮上时，如果手指或鼠标有轻微位移，就可能被判定为地图拖动，并通过 `suppressHomeClickUntil` 抑制随后的 click。

## 本轮改动

### `src/clients/mobile-h5/app.js`

- `renderHomeGroupNode()` 中把关卡文字标签从 `div` 改为同 action 的 `button`：
  - 圆形节点可点击。
  - 文字标签也可点击。
  - 两者共享同一个 `data-action` 和 `aria-label`。
- 第 4 组锁定态标签同样改成可点击按钮，点击时走 `locked` 反馈。
- `handlePointerDown()` 增加 `actionTarget` 判断：
  - 如果 pointer 起点命中 `[data-action]`，不启动地图拖动。
  - 地图拖动只从非操作控件区域开始。

### `src/clients/mobile-h5/styles.css`

- 新增 `.journey-label--actionable`：
  - 恢复 `pointer-events: auto`。
  - 保留透明背景、左对齐和原视觉样式。

### `src/clients/mobile-h5/index.html`

- 将 `app.js` / `styles.css` 查询版本从 `v=5` 升到 `v=6`，避免本地或浏览器缓存继续加载旧交互代码。

## 验证

执行：

```bash
npm run check:h5
```

结果：

- JS 语法检查通过。
- in-app browser 刷新后，直接点击 `第 1 组 · 从这里开始` 文字标签，可以进入 `第一单元` 页面。
- P02 页面显示 `已学 0 / 20`、`0%` 和 `开始学习`。
- 浏览器控制台 `error / warning` 为空。

## 接手约束

- P01 长卷首页同时有“拖动画卷”和“点击关卡”两类手势，二者必须明确分界：
  - 从空白地图区域开始 pointer 才能拖动。
  - 从 `[data-action]` 控件开始 pointer 不应启动地图拖动。
- 关卡可点击区域不能只覆盖图标。对儿童和家长来说，文字标签也是自然点击目标，必须和图标共享同一动作。
- 不要把 `.journey-label` 一律保持为 `pointer-events: none`；若标签表达可操作关卡状态，必须加可点击变体。
- 每次修复 H5 交互后同步提升 `index.html` 中的资源查询版本，避免开发验收被旧缓存干扰。
- 回归验证时至少覆盖：
  - 点击圆形节点进入单元。
  - 点击文字标签进入单元或触发锁定提示。
  - 在非控件区域拖动画卷。
  - 控制台无 error / warning。
