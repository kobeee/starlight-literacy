# 2026-05-24 一字 v9 尾音同源化修复

## 背景

[[2026-05-24-一字v9评审版太阳尾音优化]] 出片后用户回看指出尾音的"一……"与前面四次"一只 / 一道 / 这一笔 / 就是「一」"**不协调**。要解的是听感断裂，不是时机偏差。

## 根因（三处叠加）

之前的 baked 把尾音换成了**异源拼接 + 极端拉伸 + 加响**：

| 项 | 之前做法 | 问题 |
|---|---|---|
| 音源 | Unit-01 `char.mp3` 截 0.205–0.515s | 与前 4 次 edge-tts XiaoxiaoNeural -10% 不同源，听感"突然换人" |
| 速率 | `atempo=0.5,0.5,0.9`（≈0.225×，4.4 倍拉伸） | FFmpeg atempo 公认舒适区 0.5–2.0，0.225× 出现共振峰下移 + 相位伪影 |
| 响度 | `volume=1.35` | 相对前 4 句旁白被推高 35%，听感"突然吼一句" |

光标时机其实是对的，但**声学链路换了人**。

## 关键发现

`silencedetect -35dB` 跑原 raw narration 全段，发现 raw 9.359-10.704s 自带的"一。"**就是 edge-tts 在合 `script` 时一次性生成的、与前 4 段 100% 同源同 voice 同 -10% rate 的 1.35s 慢音**。

之前的 audio-plan 描述「删除 7.82-8.94s 前置「一……一。」重复，用 Unit-01 char.mp3 注入」根本与实际不符——可能是 script 经过两次修订后 audio-plan 没同步、又凭旧描述写了 char.mp3 注入路径。**最优解不是合新音，是删掉那段不必要的注入。**

## 本轮改动

**新 bake 命令一行**：

```bash
ffmpeg -y -i src/clients/mobile-h5/assets/recognition/yi/yi-v9-narration-raw.mp3 \
  -af "apad=whole_dur=12.0" -ar 48000 -ac 2 -c:a libmp3lame -b:a 192k \
  src/clients/mobile-h5/assets/recognition/yi/yi-v9-narration.mp3
```

砍掉的处理：`char.mp3` 注入 / `atempo=0.5,0.5,0.9` / `volume=1.35` / `adelay=9350`。

同步：`tools/recognition-video/builds/yi-v9/assets/audio/yi-v9-narration.mp3` 与 H5 端文件同步，`yi-v9-sun-tailvoice-check.mp4` 重渲染（1.88MB / 12.02s）。

## 验收

从最终 mp4 提音 silencedetect：

| 项 | 数值 |
|---|---|
| 主旁白 6 段 | 0.215–7.218s（同源 -10%） |
| 自然呼吸 | 7.218–9.402s（2.18s 静默） |
| **尾音"一"可听窗** | **9.402–10.667s（1.265s 同源慢音）** |
| 光标移动窗 | 9.350–10.750s（1.40s） |
| 起音偏差 | +52ms（不可察） |
| 收音偏差 | -83ms（自然衰减留白） |

声学一致性恢复：和前 4 次"一"完全同一个 XiaoxiaoNeural 在同一段语流里出来的。

## 关键决策

### 1. 注入异源音轨前必须 silencedetect raw 全段

教训：先假设 raw 不够用，跳到"截 char.mp3 + 拉伸 + 加响"路线，结果 raw 自己就有正解。**任何"raw 缺尾音"的判断都要先 `silencedetect` 全段验证**，否则会以为缺、然后从外部凑。

### 2. atempo 超出 0.5–2.0 必须停下重想

不是"加几个 atempo 串就能拉到任意倍率"。0.225× 已经超出滤镜舒适区，输出必然失真。任何想用 `atempo=a,b,c` 串接到 <0.5 或 >2.0 时，停下问：**是不是音源本来就不对**。

### 3. baked 改动同步 audio-plan 描述

`audioPaddingNotes` 必须如实写当前实际处理。本轮把描述改回："直接 `apad whole_dur=12.0`，无任何异源注入或拉伸"。否则未来 session 读 audio-plan 会再被误导。
