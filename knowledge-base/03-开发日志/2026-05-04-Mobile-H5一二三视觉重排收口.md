# 2026-05-04 Mobile H5 一二三视觉重排收口

## 背景

上一轮“一二三小世界”把产品结构从普通字卡/视频框切到了“生活里发现 -> 字形里确认 -> 用手画出来”，但用户在 in-app browser 复核后指出 UI 视觉仍然“糊一块”。本轮不继续加功能，也不继续生产 HyperFrames，而是优先按截图观感修层级、密度和主次。

## 本轮完成

- 新增 `scripts/mobile-h5-visual-audit.mjs`：无依赖调用本机 headless Chrome，按 `390 x 844` 手机视口自动截图 `首页 / 单元页 / 认字页 / 写字页 / 找字练习 / 家长证据页`，并输出 console error/warn 报告。
- `src/clients/mobile-h5/app.js`
  - 小世界场景保留隐藏 video 用于驱动 `voiceCues`，但不再把 HyperFrames 视频画面半透明叠进 P03 主场景。
  - P03 小世界移除场景内组词 chip，减少主场景和操作区互抢。
  - 单元页文案收紧为“一二三样板课”，避免长标题和装饰笔画互相压住。
  - 找字练习答案卡把 `--char-color` 提升到按钮层，让笔画提示和可选字形成一致但不混乱的层级。
- `src/clients/mobile-h5/styles.css`
  - P02 样板 hero 装饰线下移并右移，避免穿过主标题。
  - P03 小世界降低视频可见度为 `0`，加入每个样板字的轻量生活物提示：`一` 的小路/苹果/木棒、`二` 的两条线、`三` 的三条线。
  - P03 教师提示、探索 chip、CTA 保持分区，不再让主场景内部塞满解释。
  - P05 找字游戏压低主场景高度，答案卡高度和颜色重排，优先看清“哪一个是一/二/三”。
- 资源版本从 `v14` 升到 `v15`，Service Worker cache 同步升到 `starlight-mobile-h5-v15`。

## 视觉验收结论

本轮截图对比确认：

- 单元页：从“标题被横线穿过”改成主标题、进度和样板卡三层清楚。
- 认字页：从“视频字幕、白圆、字形、装饰混成一团”改成小世界内只有生活物提示 + 字形笔画，孩子一眼能看横线。
- 找字练习：选项仍然是三张可按卡片，但颜色和笔画数量更容易扫读。
- 家长中心：证据卡可见，能说明孩子学到的是“横线数量与排列”，不是随便点题。

## 研发笔记

- **P03 视频不是视觉底图**：HyperFrames 可以负责语音 cue 和离线成片，但 H5 小世界里如果直接把视频半透明叠入，会把字幕、旧场景、白圆和当前 UI 混在一起。当前策略是“隐藏视频画面，保留播放事件驱动 voiceCues”；后续真正要展示视频时，必须重新设计舞台边界，而不是 opacity 叠底。
- **截图是 UI 验收输入，不是附属产物**：这类儿童产品的质量问题经常不是 DOM 错，而是截图里“主次糊”。以后每次改 P03/P05/P11 都至少看 `390 x 844` 关键截图，再说完成。
- **卡片不是默认容器**：单元页的“样板闭环”从整张卡片退成轻量状态行后，页面更像绘本流程而不是后台面板。
- **一二三必须可区分但同属一片暖阳**：三个字共享暖米纸、蜂蜜金、低饱和辅助色，但场景线索分别绑定一条/两条/三条线，避免只是换字。
