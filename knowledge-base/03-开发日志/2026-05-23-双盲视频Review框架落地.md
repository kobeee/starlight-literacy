- t0.5–2.5s 山头 + 鸟两帧位置几乎不动，**没动画**

## 关键决策

### 决策 1 · 三方 + 主线"四独立"，不是单 Claude fresh-session

并行查 2026 年 5 月最新方向：

- Anthropic 2026-04 推出 agent-based code review（PR 场景，托管制 $15-25/PR）
- Cloudzero 2026 文章拆 Subagents / Agent View / Agent Teams 三模式
- SmartScope 2026 文章给 Claude × Codex 互审 loop 三档：SKILL.md / Plugin+Stop Hook / Pipeline
- OpenAI 2026-03-30 官方 `codex-plugin-cc` 让单 slash 跑 Codex review
- HAMY 2026-02 实战 9 维并行 subagent code review

**判断**：单 Claude fresh-session 解决不了 yi-v8 翻车（同模型同审美），必须跨模型独立。最贴合的是 SmartScope Level 1 + 模型独立性 + Jury 裁决。**关键反直觉**：Claude Code 的 YAML "subagent" 实际是**共享父上下文**，要真正独立必须 Agent tool spawn 或独立进程。

**架构**：

```
主线 Claude（orchestrator，不评不裁）
   ├── Agent tool spawn ──→ Claude Reviewer（fresh 子 agent）
   ├── Bash codex exec ──→ Codex Reviewer（独立进程 + 独立模型）
   └── Agent tool spawn ──→ Jury（fresh Claude 子 agent，只看两份 review）
```

四个独立上下文，三次真独立 review。

### 决策 2 · Jury 也独立 spawn，不由主线兼任

用户拍板"Jury 也独立 spawn"。主线天然带着 v8 实现记忆，可能下意识偏袒 Claude reviewer 的判断。第三方 fresh Claude 看两份 JSON 做裁决，独立性更彻底。**Jury 故意不读 mp4/keyframes/brief**——一旦 Jury 能看原物，就会用自己的审美校准两份 review，自我偏见回流。

### 决策 3 · 强制 3-blocker floor + reviewer fitness 审计

直接针对 v8 的"打 8.9 边界值"偷工模式：

- reviewer 输出 < 3 blocker → orchestrator 自动重派一次 + prompt 加"you missed obvious issues"
- 两 reviewer 都打 ≥ 9.0 但 build 是 needs-revision → Jury 必须标 `reviewer-fitness: questionable`
- reviewer 评分与 blocker 自相矛盾 → Jury 决定降一档 + `reviewerFitnessAction: "re-spawn-recommended"`

### 决策 4 · 默认悲观打分（worse-of-two）

Jury 合并 11 维分数默认取低，不取平均。**这个工具诞生的全部原因就是"我们一向太宽容"**。两 reviewer 明确同意时才用 average。

### 决策 5 · Codex 沙盒 `workspace-write` + prompt 软约束

需要 Codex 写 `codex-review.json`，所以选 `workspace-write`。再用 prompt + 输出 schema 验证兜底"只写这一个文件"。比 read-only + stdout 管道少一层漂移风险。

### 决策 6 · 不用 Anthropic 官方 PR review 服务

官方面向代码 PR，托管 $15-25/PR。我们要：自定义 11 维评分 / 关键帧图像输入 / 自定义 blocker 结构 / 自定义 fitness 审计。自托管 SKILL.md + Agent tool + codex exec 方案 $1/run。

## 第一性原理 · v8 翻车真正的失败在哪

按 review 维度反向看 v8.2，**问题不是工艺，是 brief 阶段动画契约缺失**：

| 表象 | 第一性原理 |
|---|---|
| 山头+鸟没动 | brief.shots[0] 没声明 wing-flap 必跨 ≥ N 帧 ≥ M 像素位移；validator 没卡 |
| 山水→橙光带突兀 | brief 没有"两镜头必须共享视觉血缘"约束（v5 cinematic 用 light-to-ink 相变桥解决，v8 路线没引入） |
| 没写字动画 | brief 的 teachingContract 缺"main timeline 必须包含 writing-action shot"约束；现状只要求 strokeOrderTail 单独存在，导致主时间线全部用 mask reveal 代替写字 |
| 笔尖在字写完后才出现 | tail-spec.finalFrame 与 main timeline 的 mizige 状态转换没在 schema 层关联；笔可以独立于字独立摆放 |

**这些都不是"画师不行"，是 brief schema 没在该卡的地方卡**。新 review 框架的价值就是让独立 Codex 视角的 spec-vs-keyframe 对比能挑出"timing-window 错配 / 动画契约缺失"，独立 Claude 视角能挑出"叙事桥缺失 / 儿童感失败"。
