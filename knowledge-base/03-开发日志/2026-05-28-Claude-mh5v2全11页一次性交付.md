## 六、本会话流程教训

1. **「整体验收」是正确的方针**：Session 1 把 12 个任务拆 1 个 1 个 audit，结果在 P04 hanzi-writer 浏览器模拟点击上耗到天荒地老（hanzi-writer 不响应 dispatchEvent PointerEvent 是真机限制，再怎么 wait 也不会过）。Session 2 batch 写完 5+3 页 + 1100 行 CSS + 1 个路由补丁，11 页全验视觉合规耗时反而少。
2. **CSS 的 `display: flex` 会覆盖 HTML `[hidden]`** — 必须显式加 `[hidden] { display: none !important; }`，这是反复踩的坑，写公共控件时必须默认带。
3. **路由表必须和 hash 字面一一对照** — 漏 `p05a` 不会报错，只会静默 fallback 到 P01，烟测才发现。下次开新 page，先动路由表。
4. 「半途审核」是 AI 容易陷的钟摆陷阱（feedback `feedback_pendulum_modification`）—— 用户明确说"整体做验收"时，把 batch 任务一次写完，最后一次性证明，比每写一页就停下来 "想想要不要审" 高效得多。
