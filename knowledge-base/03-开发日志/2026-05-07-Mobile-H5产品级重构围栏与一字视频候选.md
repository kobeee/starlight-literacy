## 推进围栏

新增 `scripts/check-mobile-h5-guardrails.mjs`，并接入 `npm run check:h5`。

围栏覆盖：

- `index.html / app.js import / sw.js` 的资源版本必须一致。
- `recognitionVideoFor()` 必须继续过滤 `status: "legacy-sample"`。
- `legacyRecognitionVideo` 只能保持 `legacy-sample`。
- `package.json` 必须暴露 `npm run audit:h5`。
- 一旦未来接入 `recognitionVideo`，必须满足：
  - `status: "official"`
  - 时长 3-8 秒
  - 24fps
  - 同时有 mp4 / webm / poster / final frame
  - 资产不能指向 `v3 / legacy / sample`
  - 不允许依赖 H5 Web Speech `voiceCues`
  - 必须声明 `audioTrack.status = "baked"`
  - mp4 / webm 真实媒体流必须包含音频 stream，尺寸 / 时长 / fps 必须与声明一致

补充：围栏也会扫描 `src/clients/mobile-h5/assets/recognition/**/*.metadata.json`。候选 metadata 可以保持 `visual-candidate-audio-blocked`；一旦 metadata 自称 `official` 或 `audioTrack.status = "baked"`，同样会触发真实媒体检查。

这条围栏的作用是：允许继续生产候选视频，但阻止“为了看到视频”把旧样片或无音频候选接进孩子主流程。

H5 运行时也已预留正式视频策略：有 baked audio 的 official 视频不会触发进页 Web Speech，`<video>` 不再被强制 `muted`，点击舞台会重播视频自带音轨。

## 音频阻塞

按新规划，正式视频不能继续依赖 H5 Web Speech `voiceCues`，应有可靠音频轨。

本轮尝试用 macOS `say` 生成离线音频轨：

```text
一条小路。一个苹果。一根木棒。都是一。
```

结果：

- 普通沙箱下生成的 AIFF 被 `ffprobe` 识别为 0 时长，ffmpeg 转码为空文件。
- 提权调用 `say` 被自动审批层拒绝。
- 删除无效音频临时文件的提权也被审批层拒绝。
- 已在 `tools/hyperframes-one/assets/unit-01/yi/.gitignore` 忽略这两个失败产物，避免误提交。
- 2026-05-07 接手续跑再次确认：普通沙箱中新生成 `/tmp/starlight-yi-tts-check.aiff` 仍是 0 秒空音频；再次申请沙箱外 `say` 生成被自动审批层拒绝。当前不能通过本机会话解决正式旁白资产。

因此本轮没有把候选视频接入 H5 主流程。下一步必须先解决 baked audio，再把候选升级为 official。

## 验证结果

通过：

```bash
npm run check:h5
npx hyperframes lint
npx hyperframes inspect --at 0.3,0.8,1.6,3.2,4.8,5.7 --json
npx hyperframes render -o renders/yi-stage-official-candidate.mp4 --fps 24 --quality draft --workers 1
/Users/elvis/.agents/skills/starlight-recognition-video/scripts/verify_hyperframes_video.sh tools/hyperframes-one renders/yi-stage-official-candidate.mp4
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,r_frame_rate,duration,nb_frames -of default=noprint_wrappers=1 tools/hyperframes-one/renders/yi-stage-official-candidate.mp4
```

关键输出：

- `Unit-01 course model ok: 20/20 characters, 11 required fields.`
- `Mobile H5 speech rhythm ok: segmented queue, pause map, voice preference and cancellation are present.`
- `Mobile H5 guardrails ok: v19 resources, legacy gate, visual audit hook, official video policy.`
- 额外媒体围栏探针：当前 `yi-stage-official-candidate.mp4` 只有 video stream、无 audio stream；若被伪装接入 official，会被 `check-mobile-h5-guardrails.mjs` 拒绝。
- HyperFrames lint：0 error，1 warning（`composition_file_too_large`，维护性 warning）
- HyperFrames inspect：0 issue
- MP4：`1280x800`，`24/1 fps`，`5.833333s`，`140 frames`
- final frame 人工查看：主横线清楚，final frame 可作为 fallback/poster

未通过 / 环境阻塞：

```bash
npm run audit:h5
```

失败原因已被脚本增强为可读输出：

- 缓存 `chrome-headless-shell`：`MachPortRendezvousServer ... Permission denied (1100)`，`SIGTRAP`
- 系统 Chrome：启动前 `SIGABRT`

结论：当前沙箱无法启动 headless Chrome DevTools endpoint。脚本已改为逐个尝试 Chrome 候选，并输出每个候选的 stdout/stderr；后续在允许 Chrome 启动的环境中重跑即可。
