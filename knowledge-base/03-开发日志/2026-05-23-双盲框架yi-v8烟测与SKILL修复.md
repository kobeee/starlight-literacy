## SKILL 模板 4 处缺陷 · 现场学血

烟测过程中 codex reviewer 跑了 3 次才成功，每次失败都是 SKILL 模板写错。原地修回，对应 commit 见 `.claude/skills/video-review/SKILL.md` 改动。

### 缺陷 1 · codex exec trailing positional 被 `--image` 贪婪吞掉

SKILL 模板原句：

```bash
codex exec --model gpt-5-codex --image $(jq...) "PROMPT"
```

`codex exec --help` 把 `-i, --image <FILE>...` 定义为 trailing multi-value 选项（clap 贪婪解析）。把 `"PROMPT"` 作为 positional 放在 `--image` 后面，clap 把 prompt 字符串当成**第 12 张 image 文件**吃掉，positional `[PROMPT]` 为空。codex 退化到 *Reading prompt from stdin* 模式，但 Bash 工具子进程没有人给 stdin 写东西 → **永远挂起**。第一次跑 15 分钟没动静、CPU 时间累计 0.15s。

**修复**：prompt 改走 stdin pipe：

```bash
printf '%s' "$PROMPT" | codex exec --sandbox workspace-write "${IMG_FLAGS[@]}"
```

stdin EOF 由 printf 自动给到，codex 立即拿到 prompt 开跑。

### 缺陷 2 · 硬编码 `--model gpt-5-codex` 在 ChatGPT account 不支持

第二次跑时 codex 真开跑了但立即报：

```
ERROR: {"detail":"The 'gpt-5-codex' model is not supported when using Codex with a ChatGPT account."}
```

`codex login status` 显示 `Logged in using ChatGPT`，账户默认模型是 `gpt-5.5`（在 config.toml 里可见 `[tui.model_availability_nux] "gpt-5.5" = 2`）。SKILL 模板写 `gpt-5-codex` 是给 API key 账户的写法，跟当前登录态对不上。

**修复**：去掉 `--model`，让 codex 用账户默认。第三次跑通，11s 跑完 "say hi" 校准、整轮 review 4 分钟。

### 缺陷 3 · `-i` flag 用单 token `$(jq...)` 不稳，应 per-image

原句 `--image $(jq -r '.inputs.keyframes[]' ... | tr '\n' ' ')` 把 10 张图当作一个空格分隔 token，依赖 shell 二次分词 + clap multi-value 解析双重正确。修复用 bash array `${IMG_FLAGS[@]}`，每张图独立 `-i FILE`，可清晰追加 `reviewSheet`（烟测验证 reviewSheet 对 codex 看全帧叙事很关键）：

```bash
IMG_FLAGS=()
while IFS= read -r line; do IMG_FLAGS+=( -i "$line" ); done < <(jq -r '.inputs.keyframes[]' "${run_dir}/input-pack.json")
SHEET=$(jq -r '.inputs.reviewSheet // empty' "${run_dir}/input-pack.json")
[ -n "$SHEET" ] && IMG_FLAGS+=( -i "$SHEET" )
```

### 缺陷 4 · spawn prompt 把所有规则塞进去违反单一信息源

SKILL 模板原本给 Claude reviewer / Codex reviewer / Jury 的 prompt 都是一大段，复述 input-pack 路径、output 路径、no-read 清单、3-blocker floor、validator 禁令、完成时打印什么……所有这些**已经在各自 SKILL.md 里写过一遍**。两套规则同义但两源，注定会漂移。

用户指出（中文原话）："**不要上下文全都塞到 prompt 里，通过 spec 的方式，让 codex 自己去读文档**"。

**修复**：spawn 时 prompt 只传两件事：

```
Read .claude/skills/video-review-{claude,jury}/SKILL.md and follow it exactly. Use run_dir=<abs>.
```

或对 codex：

```
Read tools/recognition-video/codex-skill/starlight-video-reviewer/SKILL.md and follow it exactly. Use run_dir=<abs>.
```

所有 reviewer/jury 行为规则的唯一来源是各自 SKILL.md（事先 grep 验证过 jury SKILL line 17/27/153 + claude SKILL line 27/142 都明文写着完整 no-read 清单）。orchestrator 不再持有第二份契约。

新加 **Hard rule 8**：「Spawn prompts must be spec-pointers, not rule recitations」，把这个原则写进 SKILL 当永久约束。
