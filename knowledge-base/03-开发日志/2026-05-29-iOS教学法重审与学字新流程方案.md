## 1. 决策经过（三轮对话把问题逼到根上）

1. **第一轮**：用户指「认字那里小孩子不知道咋认」+「这版 app 字好多」。
2. **第二轮**：澄清——"认字"指**一开始介绍汉字那里一堆字、咋学**；"字好多"指**界面都是字**。
3. **第三轮**：要求重审产品理念——"幼龄儿童什么方式最容易最有效认得汉字"，并拍板按新方案走、不要 AI 再纠结"动摇了什么定稿"。

**AI 自我修正**：前两轮 AI 一直在"字源用插画还是视频"里优化，**没质疑"字源该不该当主路径"这个前提**。第三轮才跳出来，靠第一性原理 + 洪恩反馈 §3 定位出真问题。

**贯穿病根**：app 按"用户识字"做，可用户是**还不识字的 3-6 岁孩子**——每屏都漏这个假设。

**核心结论（详见方案文档）**：
- 幼儿认字 = 把新符号(形)挂到已有的音义上 + 整体图形记忆 + 多通道 + 高频复现；理解"来历"是天花板不是地基。
- **"字源真讲"是护城河（卖给高知家长，普通用户不感知）≠ 主教学法**。洪恩反馈 §3 line 390 自己就这么标的。
- 字源只对真象形字（六书象形类，约 15%）成立；当全字库地基必滑向直映法（红线 §7.3）。
- **新主路径**：认读绑定(图音字) → 动手指认 → 跟读 → 写 → 复现；字源降级为象形字彩蛋。
- **字源彩蛋不做 mp4 视频**：静态插画 + 微动效即可，理由 = ROI 数学（砍cinematic §1.4 算过 1300 字视频"数学上不可能"）+ 视频治标不治本（病根是文字当主角，不是动效不够炫）+ 红线 §7.8。

## 3. 新 session 执行入口（建议顺序）

1. **先修学习链路断点 C1-C3**：这是"玩不下去"级别的断点，优先级高于视觉打磨（Codex 建议，认同）。
2. **教学法主路径 A1-A6**：按方案 §3 五步重构 P03/P05 + 首页去字墙 + 文案下沉。**碰页面角色/跳转前先对照 [[../01-产品设计/USER_FLOW]] 登记**（偏离 #9-#12 已登记，执行时落实）。
3. **视觉资产 B1**：gpt-image-2 产实物图（同时喂 A1 认读图 + A2 看图认字图 + 象形字彩蛋形变素材），调用见 [[../../memory/reference_gpt_image_2_calling]]。
4. **顺手修 B2/B3 两个 layout bug**：便宜、观感收益高。
5. **补验证 B5/B6**：声音实听、复杂字 HID 手感。

**约束重申**：不做 mp4 视频（字源彩蛋用静态插画+微动效）；只播 baked mp3 禁 OS TTS；零挫败容差保留；付费/邀请红线不动。未 git commit（需用户许可）。
