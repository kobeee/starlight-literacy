# 2026-05-05 Mobile H5 产品级重构规划

## 背景

本轮继续 review 了前几轮 Mobile H5 优化结果。结论不是“再把页面修漂亮一点”，而是当前方向存在产品系统性问题：

- `一 / 二 / 三` 被做成了特例小世界，后续 17 个字会明显掉档。
- P02 单元页仍围绕“阳光三小步”，没有呈现 Unit-01 20 字完整路径。
- HyperFrames 只有 `一`，且 `一` 当前样片依赖 H5 Web Speech、时长和表现力都未达正式标准。
- 练习、测验、书写和家长证明链路还不能支撑“学会了”的产品承诺。
- 生图工具前面被用于局部补图，下一阶段必须改成受控资产生产能力。

## 决策

建立新的权威规划：

- [[01-产品设计/Unit-01产品级重构执行规划|Unit-01 产品级重构执行规划]]
- [[06-素材资源/Unit-01素材与生图生产规范|Unit-01 素材与生图生产规范]]

后续实现严格按新规划推进。旧的“一二三小世界”沉淀只保留“生活承载物优先于裸线条”的洞察，不再作为 Unit-01 整体产品方向。

## 新执行顺序

```text
Phase 1：修进度和学习证据 + 补统一课程字段
Phase 2：P02/P03/P05/P11 重构为 20 字完整路径
Phase 3：用生图工具建立 Unit-01 资产体系
Phase 4：重做“一”标准视频样片
Phase 5：只做 二 / 三 / 人 / 山 / 火 代表字视频
Phase 6：验证、部署、再决定是否扩到 20 字
```

## 关键接手约束

- 不再继续单独打磨 `一 / 二 / 三`，除非它服务完整 20 字模型。
- 先保证所有 20 个字都有 native micro-lesson，再把视频作为增强层。
- 生图不画汉字，不画拼音，不画 UI 文案；汉字由代码 / 字体 / SVG / canvas 控制。
- 所有项目使用的生成图必须落盘到 workspace，并记录 prompt、用途和版本。
- `一` 当前视频不是正式标杆，要重做成新标准样片。
- 代表字视频只做 `二 / 三 / 人 / 山 / 火`，不允许模板换字批量冒充完成。
- 家长中心只展示学习证据，不展示虚假的“已掌握”。

## 下一步

下一轮进入实现时，先做 Phase 1：

1. 修复 progress 跨天清空、答错点亮、双推进、资源版本和 SW 缓存问题。
2. 在 `src/shared/unit-01.js` 补统一课程字段。
3. 不做大 UI 改版，先让数据和学习状态可信。

Phase 1 通过后，再进入 P02/P03/P05/P11 的结构重构。
