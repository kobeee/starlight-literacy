# 2026-05-02 Mobile H5 认字动画教学化改造

## 本轮讨论结论

用户指出：动画不是炫技，而是为了吸引孩子，并辅助孩子更好地记忆和认识对应汉字，本质上是教学手段。HyperFrames 也不应该被预设为竖屏视频，而应该服从产品顶层设计和页面形态。

本轮据此修正项目认知：

- HyperFrames 是认字教学动画生产工具，不只是“视频增强层”。
- P03 认字页要从“静态插画页 + 视频补丁”升级为“认字教学舞台 + 稳定信息区”。
- 动画比例、时长和内容结构由教学目标决定，而不是由工具默认模板决定。
- 当前 Mobile H5 只是市场验证版，离理想产品还有明显差距。随着动画教学加入，P03 以及后续认 -> 写 -> 练的整体节奏都需要继续重构。

## 研发笔记

### 1. 旧方案的问题

旧 HyperFrames “一”字样片是 `1080x1920` 竖屏完整页，内部包含大字、拼音、组词和下一步按钮。它适合验证 HyperFrames 可用性，但不适合作为 P03 上半屏媒体资产。

如果直接接入 H5，会出现两个问题：

- P03 自己已有大字、拼音、组词和 CTA，信息会重复。
- 视频会反过来定义页面结构，违背“产品顶层设计在上，工具在下”的原则。

### 2. 新方向

P03 中的 HyperFrames 资产应是横向或接近横向的“认字舞台”：

```text
场景轻入场
  -> 字形关系高亮
  -> 大字/读音短暂收束
  -> 平静最终帧
```

H5 页面保留稳定信息区，承接孩子看完动画后的确认与操作。

### 3. 接手约束

后续不要再把 HyperFrames 默认为竖屏整页；也不要把“动画教学”退化成静态页上的一个可有可无视频卡片。每个字应先有教学钩子，再决定动画形态。
