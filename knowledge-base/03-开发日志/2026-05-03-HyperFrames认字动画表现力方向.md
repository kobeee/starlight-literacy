# 2026-05-03 HyperFrames 认字动画表现力方向

## 今日结论

用户指出当前“一”字 HyperFrames 样片虽然技术上已完成嵌入、播放和降级验证，但表现力仍偏单调，像“平平无奇的视频动画”，对小孩认字的帮助有限。

本轮重新确认：后续 HyperFrames 动画不应只做“字形描线”或“静态教学板轻动效”。它应该更像一段儿童可感知的小片段：有角色、有动作、有具体物、有记忆钩子，但最后必须清楚回到汉字本身。

## 关键判断

### 1. HyperFrames 能做逐帧静态图动画

HyperFrames 可以支持类似逐帧动画的表达：

- 多张 PNG / WebP 按 `data-start`、`data-duration` 依次出现，形成翻页式动画。
- 使用 sprite sheet，通过 CSS `background-position` 或 GSAP `steps()` 做切帧。
- 使用 6-10 张关键帧插画 + 少量位移、缩放、淡入，模拟更完整的动画。

这类方案适合“角色做一个明确动作”的认字短片，例如拿起、放下、推开、点亮、长出、合拢等。

### 2. 生动不等于偏离认字

用户举例“狮子吃一个番茄、一个玉米、一个火腿肠”是为了说明可以更生动，不是要固定成这个剧情。

后续不能把动画做成角色短剧后忘记认字目标。每条片子必须同时满足：

- 字形：孩子看得出这个字为什么长这样。
- 字义：孩子看得出这个字在表达什么。
- 字音：孩子知道怎么读，能和页面语音/TTS 衔接。

对“一”而言，单纯“狮子吃很多东西”容易表达成“吃东西”或“很多食物”，不够聚焦。更合适的是“一个角色只拿/吃/找到一个物品”，再让这个“一个”变成“一条横线”和汉字“一”。

## 新设计方向

### 方向 A：逐帧角色动作 + 字形收束

适合“一”字：

```text
一只小动物出现
  -> 只拿起一个番茄 / 一个玉米 / 一个苹果
  -> 画面强调“一个”
  -> 物品下方出现一条平平横线
  -> 横线收束成大大的“一”
  -> final frame：一个物品 + 一条横 + 汉字“一” + yī
```

重点不是“吃了什么”，而是“只有一个”和“一条横线”建立连接。

### 方向 B：场景隐喻 + 角色参与

适合横线类字：

```text
小动物在草地上铺一条小路
  -> 小路从左到右变平
  -> 小路变成一条金色横线
  -> 横线落进田字格，成为“一”
```

这比纯线条描画更有动作和故事，但仍以字形为主。

### 方向 C：关键帧绘本动画

每个字先生成 5-8 张关键帧插画：

1. 角色/场景引入。
2. 具体物或动作出现。
3. 数量/形状被强调。
4. 图像抽象成字形。
5. 汉字、pinyin、词语静态收束。

HyperFrames 负责把这些关键帧按时间轴排布、加轻微动效、输出 `mp4 / webm / poster / finalFrame / metadata`。

## 接手约束

- 不要把 HyperFrames 动画继续做成单调的描线板。
- 可以使用角色、逐帧静态图、sprite sheet、关键帧绘本动画，提高儿童注意力和记忆点。
- 每个字先写“教学分镜”，再写 HTML/GSAP，不要先堆视觉元素。
- 角色和剧情必须服务字形/字义/字音，不要喧宾夺主。
- 片长仍控制在 3-8 秒，P03 当前优先 4-6 秒。
- final frame 必须可作为 poster/fallback：安静、清楚、能回答“这个字是什么/为什么这样认”。

## v4 语音听感纠偏

用户随后指出，虽然 v3 已经解决“视频中字幕需要同步播读”的问题，但实际听感仍有明显 AI 味，尤其是语速、停顿和衔接很糟糕。

本轮先尝试把 cue 拆成更细的“发现 / 复述 / 抽象 / 归纳”节奏，例如 `看，一个苹果`、单独读 `一`、`平平一条`、`也是一横`。复盘后确认这条路不适合当前浏览器 TTS：

- 句子拆太碎会让 `speechSynthesis` 像在拼接碎片，听起来更机械。
- `pitch` 偏高、`rate` 偏低会强化 AI 儿童腔，不像自然老师带读。
- 每条 cue 调用 `speechSynthesis.cancel()` 会硬切上一句，导致衔接更差。
- 认字页进入时原本还会自动读 `一，一个的一`，随后视频 cue 很快接 `一个苹果`，几乎没有停顿，这是用户明确指出的主要糟点。

已做纠偏：

- `src/clients/mobile-h5/app.js` 新增中文语音优先选择，默认 `rate` 调整到约 `0.9`、`pitch` 回到 `1`。
- 视频 cue 播放时使用 `interrupt: false`，不再每句都 cancel 上一句。
- `一` 的 `voiceCues` 从 7 个碎 cue 回退为 4 个主句：`一个苹果 / 一条小路 / 一根木棒 / 都是一`。
- 对有 `recognitionVideo.voiceCues` 的字，进入认字页不再自动读完整字音；点击视频/喇叭重播时也只重播视频 cue，不再先读 `一，一个的一`。
- 保留无视频 cue 字的原自动读字逻辑。

下个 session 首要任务：

1. 先本地打开 H5 实听“一”字开头，确认 `一，一个的一` 与 `一个苹果` 不再抢读。
2. 如果仍觉得 TTS 听感差，不要继续靠标点和碎 cue 修；优先改为正式音频资产或后端/离线 TTS 生成音频轨。
3. 再继续讨论趣味性和画面细节，避免在语音基础体验未稳时继续堆表现力。
