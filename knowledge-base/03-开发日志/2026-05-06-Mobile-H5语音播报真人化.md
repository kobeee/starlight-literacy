# 2026-05-06 Mobile H5 语音播报真人化

## 背景

用户反馈当前 H5 语言播报“太 AI”，主要问题不是单个字读错，而是 Web Speech 连续平铺播报：停顿太少、节奏太机械、提示语和课程正文容易糊在一起。

本轮目标是先在现有 Web Speech 能力内，把播报从“一整段一次性读完”改成接近真人讲课的分段表达。

## 本轮改动

- `src/clients/mobile-h5/app.js` 新增 `SPEECH_STYLE_PRESETS`：区分 `lesson / cue / discovery / feedback` 几类语气，分别控制 `rate / pitch / pauseScale`。
- 新增标点停顿表 `SPEECH_PAUSE_MS`，中文逗号、顿号、句号、问号、叹号、省略号等都有不同停顿。
- 新增 `splitSpeechText()` 和 `speakSegments()`：
  - 先按中文语义标点切分文本。
  - 每段单独创建 `SpeechSynthesisUtterance`。
  - 上一段 `onend` 后延迟指定毫秒再进入下一段。
- `speak(item)` 不再把完整课程文案一次性塞给 TTS，而是：
  - 先播字音和常用组词。
  - 再播 `nativeTeachingCue()` 拆出的教学提示。
  - 最后播字形钩子和生活映射。
- 新增中文 voice preference：优先选择系统中文女声 / 普通话 voice，并在 `voiceschanged` 时清理缓存。
- `cancelSpeech()` 会清掉当前 utterance 和后续队列，避免切页、点按钮、视频 cue 之间串音。
- `package.json` 的 `npm run check:h5` 接入 `scripts/check-mobile-h5-speech.mjs`，固定校验分段队列、停顿表、voice preference 和取消逻辑存在。

## 验证

本地校验：

```bash
npm run check:h5
```

期望输出包含：

```text
Unit-01 course model ok: 20/20 characters, 11 required fields.
Mobile H5 speech rhythm ok: segmented queue, pause map, voice preference and cancellation are present.
```

本轮自动校验能确认代码结构和部署产物已经具备“分段、停顿、选声、取消队列”能力；真实听感仍需要在浏览器或真机上实听，因为不同系统的 Web Speech voice、音色和断句行为不完全一致。

> [!warning] in-app browser 限制
> 当前 Codex desktop 线程里虽然有 Browser Use 插件，但没有暴露 Node REPL `js` 执行工具，无法按插件要求直接驱动 in-app browser 做点击和实听验证。因此本轮只能做本地结构校验、远端构建校验和公网资源内容校验；“听起来像人”的最终判定仍以真机 / 浏览器实听为准。

## 后续判断

这版是 Web Speech 层面的节奏优化，不是最终音频资产方案。如果真机实听仍不够自然，下一步不应继续堆奇怪标点或极端 `rate / pitch`，而应进入正式音频方案：

- 为核心教学句生成可控 TTS 音频资产。
- 或将认字视频的音频轨合进 HyperFrames 成片，H5 只负责播放视频和降级文案。
- 对普通反馈语保留 Web Speech，核心教学语使用正式音频。
