# 2026-05-30 · 生图链路根因诊断与打通

> 本篇只讲「为什么"gpt-image-2 一直没解决"、现在怎么通的」。
> 库存清单 / 缺口盘点见姊妹篇 [[2026-05-30-iOS与Unit01图片素材库存复核]]（codex 客户端记录）。

## 一句话

"gpt-image-2 生图一直没解决"不是模型不行、也不是工具链缺失，是**调用姿势 + 一次误判**叠加出来的假象。模型能力（gpt-image-2）和两条生图路径其实都在，本轮定位根因、验证可用链路、产出 Unit-01 实物场景图。

## 根因诊断（三层）

### 1. 知识库旧记的"主路径"在当前环境会误导

旧 memory/文档写「主路径 = `codex exec` 进 agent 调内置 image-generation 工具」。按此跑：

```bash
printf '%s' "$PROMPT" | codex exec --sandbox workspace-write -C "$PWD"
```

结果 **EXIT=0、还回显了我让它保存的目标路径**，但那个路径下**没有文件**，日志里也看不到 tool call。当时据此误判为「codex 没有 image 工具、静默假装成功」。

### 2. 真相（诚实修正上一条 —— 我判断错了）

codex **有** `imagegen` system skill（`~/.codex/skills/.system/imagegen/SKILL.md`）+ 内置 `image_gen` 工具，**不需要 OPENAI_API_KEY**。那次 smoke **其实真的出图了**，落在：

```text
~/.codex/generated_images/<session-id>/ig_*.png    # RGB 1254×1254
```

误判根因两条：

- codex built-in `image_gen` **不接受目标路径参数**。skill 明文："Do not rely on a destination-path argument… generate first then move/copy from `$CODEX_HOME/generated_images/...`"。它把图存默认目录，只是把我 prompt 里要求"打印路径"的那串字符回显了出来——那串路径当然是空的。
- 我没去 `$CODEX_HOME/generated_images/` 找就下结论。

**教训：codex 生图后必须去 `generated_images/<session-id>/` 取图，不能信它回显的路径；EXIT=0 + 回显路径 ≠ 文件已落在该路径。**

### 3. 透明的真实限制（不是误解，是真限制）

- gpt-image-2（built-in 和代理底层都是它）**不支持原生透明**：
  - 代理实测 `400 Transparent background is not supported for this model`；
  - imagegen skill 也写明 `gpt-image-2 does not support background=transparent`。
- skill 设计的透明做法 = **prompt 一个 flat chroma-key 背景 + 本地 `$CODEX_HOME/skills/.system/imagegen/scripts/remove_chroma_key.py` 去背**。
  → 这跟本轮用的「magenta `#ff00ff` 出图 + PIL 抠透明」**是同一套方法**，不是我自创的偏门。
- 真·原生透明只有 CLI fallback `gpt-image-1.5 --background transparent --output-format png` 能给，**需要 OPENAI_API_KEY 且须用户确认**（属模型降级路径，禁止静默切换）。
- ⚠️ 2026-05-15 调研日志写"codex 内置 5/5 出真 RGBA 透明"在当前环境**复现不了**，按上面的限制理解。

## 两条等价可用路径（都不需要 openai key）

| 路径 | key | 透明做法 | 何时用 |
|---|---|---|---|
| codex built-in `image_gen`（imagegen skill） | **不需要** | chroma-key + `remove_chroma_key.py` | codex 客户端 / agent 上下文里 |
| aicodewith proxy + Responses API + `image_generation`（wrapper `gpt-5.5`） | sk-acw 代理 key（`~/.codex/auth.json.aicode`），**非 openai key** | chroma-key + `chroma-key-to-alpha.py`(PIL) | 脚本化 / 批量 / Claude 侧 Bash |

两条底层都是 gpt-image-2 + chroma-key 后处理，结果等价。本轮 Claude 侧走 proxy（脚本化批量方便），codex 侧走 built-in。

旧两个脚本接错线、无法用，已被废弃认知：`generate-gpt-image-assets.mjs`（拿 sk-acw key 打 `api.openai.com`，端点不对）/ `generate-via-responses.mjs`（端点对但读空的 `auth.json`）。
