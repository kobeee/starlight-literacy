# 2026-04-29 Mobile H5 验证版落地

## 背景

原计划先做微信小程序，但个人主体无法顺畅接入微信支付；直接切 iOS 又会引入开发者账号、App Review、IAP 等额外成本。阶段目标调整为：先用 Mobile H5 做市场验证，验证孩子是否愿意学、家长是否认可、Unit-02 的 9.9 元付费意向是否成立。

本轮原则：
- 不做桌面 Web 产品，只做“手机浏览器里的 App 体验”。
- 复用现有移动端视觉稿和导出图片，不重新做 PC 版视觉稿。
- 先跑通核心链路，真实支付、正式 TTS、完整笔顺识别后置。
- 目录结构按多端 + 前后端分离调整，避免 H5 临时实现污染小程序目录。

## 修复的问题

- **P01 长卷被误实现成普通页面滚动**：首轮为了让当前关首屏可见，把长卷图当作 `.home` 的 CSS background，并使用 `overflow-y:auto`。这破坏了“长轴画卷可拖动”的产品形态，也导致视觉稿的底图叠层缺失。已改为 390×1800 的独立画卷 canvas，通过 pointer 事件自定义拖动，默认取景到当前关附近。
- **P01 底图与视觉稿不一致**：首轮 H5 只引用 `images/p01-bg-redraw-road-centered-20260426.png`，漏了视觉稿正式使用的 `images/p01-pastoral-overlay-20260426.png` 和 `images/p01-animal-edge-overlay-20260426.png`。已在首页补齐背景、暖米滤镜、田园叠层、动物边缘叠层和远方雾带。
- **小屏可能出现浏览器外层滚动**：`.phone` 原来有 `min-height:660px`，小视口下会让 body 参与滚动。已改为视口内固定手机壳高度，首页拖动只发生在 App 内部画卷层。
- **Service Worker 干扰开发验收**：localhost 下缓存了旧 CSS/JS。改为本地环境自动 unregister，生产域名才注册 SW。
- **书写页“跳过”分支错误**：原逻辑先把笔画数设满再调用 `completeStroke()`，导致直接 return。新增 `finishWriting()` 统一处理跳过和自然完成。
- **临时图片质量不稳定**：部分旧导出图带透明棋盘格或不是正式学习插画。H5 暂时按 group 复用安全成稿图，正式逐字插画后续替换到共享配置。
- **家长中心学习时长异常**：旧缓存导致显示几百分钟。新增 `dayKey` 按天重置，并限制展示上限。
- **付费页旧视觉稿文案冲突**：原 P09 截图背景里有“宝宝已学会 20 个字”旧文案，与真实进度冲突。改用纯插画背景，真实文案由 H5 渲染。

## 技术决策

### 1. Mobile H5 不是“Web 版”

本轮没有做桌面响应式站点，而是固定为移动端体验。桌面浏览器只呈现居中的手机画布，产品验证对象仍然是手机用户。

### 2. P01 首页必须保留长轴画卷交互

P01 的产品形态不是普通页面滚动，也不是一张固定背景图。H5 实现应遵守：
- 画卷本体是固定设计坐标系 `390×1800`，按手机容器宽度缩放。
- 首屏只是取景窗口，默认定位到当前关附近；用户拖动时移动整张画卷。
- 不使用浏览器 body 滚动承载 P01 首页，也不要把长卷只挂成 `.home` 的 background。
- 正式资源组合为：
  - `images/p01-bg-redraw-road-centered-20260426.png`
  - `images/p01-pastoral-overlay-20260426.png`
  - `images/p01-animal-edge-overlay-20260426.png`
- 不恢复已废弃的起点小房子方案，不把 `p01-start-house-*` 或 `p01-start-home-entrance-*` 当作 P01 首页正式资产。

### 3. H5 先不引入框架

为了快速落地和降低依赖风险，第一版是 dependency-free 静态 H5：
- 不安装 React/Vue/Vite。
- 使用原生 ES module、CSS、DOM 状态机。
- 用本地 Node `http` server 预览。

后续如果 H5 继续演进，再评估引入 Vite + React 或其他框架。

### 4. 认字动画暂不用 Hyperframe

用户提到可以尝试 Hyperframe。实际检查 npm registry 时未找到 `hyperframe` 包，因此本轮没有把未知依赖作为阻塞点。

当前替代方案：
- 插画入场 + 光点层
- 大字描边/描红感动效
- 语音按钮脉冲
- CSS/SVG 原生动画

后续若确定 Hyperframe / Remotion 资产管线，可把 P03 认字动画替换为视频或帧动画资产。

### 5. 后端暂不启动

Mobile H5 MVP 暂不需要真实后端：
- 进度：`localStorage`
- 付费：只记录意向
- 分享：前端 Canvas 生成海报

真实后端后续用于：
- 用户身份 / session
- 学习进度同步
- 支付订单 / 权益
- 内容发布和版本控制

### 6. VPS 上线采用静态 nginx 容器

线上没有跑本地 Node 开发服务器，而是构建静态 nginx 容器：

- 容器只绑定 `127.0.0.1:4173`，不直接暴露公网端口。
- host nginx 根据 `server_name starlight.escapemobius.cc` 反代到容器。
- host nginx 在 `/` 显式返回 `302 https://$host/src/clients/mobile-h5/`，避免容器或 nginx 默认绝对跳转生成 `http://...`。
- 当前观察到 VPS `*:443` 由 `sing-box` 监听，公网 HTTPS 由 Cloudflare / 既有前置链路进入源站；本轮不改动 443 前置配置。

详见 [[05-技术文档/Mobile-H5-VPS部署Runbook|Mobile H5 VPS 部署 Runbook]]。

## 当前限制

- 书写判定只是简化“划一下推进一笔”，不是正式笔顺识别。
- 音频使用 Web Speech API，未接入正式儿童语音 TTS 文件。
- 小组练习和单元测验已有状态机骨架，但题型仍是简化点击选择。
- 拖拽匹配题型未做真实拖拽版。
- 分享只生成本地海报 / 复制链接，不调用微信分享能力。
- 付费页只记录意向，不接真实支付。

## 2026-04-30 后续纠偏

用户指出：Mobile H5 是真实用户体验，不能因为视觉稿里有“已通关 / 当前关居中”的示例状态，就让首次进入看起来像前面几关已经玩过。

已在 [[2026-04-30-Mobile-H5首屏进度状态纠偏]] 中修正并记录：

- P01 首页节点改为真实进度驱动，首次进入显示第 1 组可开始，后续组锁定。
- P01 默认取景从固定视觉稿中段，改为跟随真实当前组。
- P02 首次进入显示 `已学 0 / 20` 和 `0%`。
- 第二单元 / 付费引导只有 Unit-01 全部完成后才允许进入。
- 保留原 `localStorage` key，兼容迁移旧进度，不通过清缓存掩盖状态 bug。
