# 2026-05-06 Mobile H5 正式认字视频接手记录

## 背景

用户确认当前线上 / 本地 H5 认字页看不到视频，询问是否因为视频没做完。

结论：**是的。当前主流程无视频是主动产品降级，不是视频文件丢失，也不是播放 bug。**

## 当前代码状态

- 旧 `一` 视频文件仍在：
  - `src/clients/mobile-h5/assets/recognition/yi/yi-stage-v3.mp4`
  - `src/clients/mobile-h5/assets/recognition/yi/yi-stage-v3.webm`
  - 对应 poster / final frame / metadata 也仍保留。
- `src/shared/unit-01.js` 里 `一` 仍保留 `legacyRecognitionVideo`，状态是 `legacy-sample`。
- `src/clients/mobile-h5/app.js` 的 `recognitionVideoFor(item)` 会过滤掉 `legacy-sample`：

```js
const video = item.recognitionVideo || item.legacyRecognitionVideo || null;
if (!video || video.status === "legacy-sample") return null;
return video;
```

因此 P03 当前会走 `lesson-stage--native` 原生认字舞台，而不是渲染 `<video>`。

## 为什么不能直接打开旧视频

不要通过改状态、删判断或把 `legacyRecognitionVideo` 当 `recognitionVideo` 来“恢复视频”。

旧样片被下线的原因：

1. 时长约 `9.83s`，超过新规划的 `4-6s` 标准样片要求，最多也不应超过 `8s`。
2. 依赖 H5 Web Speech / `voiceCues`，不是可靠的正式音频轨。
3. 它是 2026-05-03 的救援样片，不是 2026-05-05 产品级重构后的正式 baseline。
4. 如果直接打开，会让产品看起来“有视频了”，但实际绕过了新质量门槛。

## 下个 session 的目标

下个 session 要一步到位解决“当前认字页没有正式视频”的问题，目标不是恢复旧样片，而是：


## 正式「一」样片验收口径

内容要求：

- 4-6 秒，最多 8 秒。
- 0.8 秒内出现字形钩子：一条小路 / 一个苹果 / 一根木棒收束到平稳横线。
- 字形必须是主角，场景只辅助。
- 不出现 App chrome、按钮、奖励风暴、密集字幕、伪中文、伪拼音。
- 最后一帧要安静、清楚，可直接作为弱网 poster / final frame。
- 音频不能继续依赖 H5 Web Speech 临场拼接；优先烘焙到视频或使用稳定音频文件。

技术要求：

- HyperFrames composition deterministic：不用 `Date.now()`、`Math.random()`、网络请求。
- 每个 timed visible element 有 `class="clip"`、`data-start`、`data-duration`、`data-track-index`。
- GSAP timeline paused 并注册到 `window.__timelines`。
- 产物写入 H5 资产目录和 HyperFrames renders 目录，并同步 metadata。

- 控制台无 error / warn。

## 禁止事项

- 禁止直接把 `legacy-sample` 改名为正式视频。
- 禁止为了“看到视频”删除 `recognitionVideoFor()` 的 legacy gate。
- 禁止把未验收视频接入为正式 `recognitionVideo`。
- 禁止继续只修 UI 文案或 Web Speech 节奏来掩盖视频缺失。
- 禁止把生成图中的汉字 / 拼音作为教学画面主体；汉字必须由代码、字体或 SVG 控制。
