# 2026-05-15 生图能力调研与流水线纠偏

## 背景

05-14 收口 HyperFrames spritesheet 标准化流程时，日志写下结论：

> fallback CLI 默认模型为 `gpt-image-2`；该模型不支持直接透明背景。

该判断让整条流水线绑死在 chroma-key 路径上。但 gpt-image-2 是 2026-04-21 才发布的版本，项目内的几条核心约束（无中文、无参考图、必须 chroma-key、不能多图输入）来自更早的模型时代，4 个月没有重新调研。本轮重新验证。

## 调研结论

用本地 codex CLI 跑 5 次独立验证（PIL 像素级检查），结论：

| 能力 | 旧假设 | 新结论 |
|---|---|---|
| RGBA 真透明 PNG | 不支持 | **支持**（5/5 成功，prompt 明确写 `transparent PNG with alpha channel (RGBA)` 即可） |
| 中文字 | 不能画 | 99% 准确（但教学场景仍由 HTML/CSS 渲染） |
| 参考图风格锚定 | 不支持 | **支持**（B 任务用 style board 参考图成功输出统一水彩风格） |
| 纯 prompt 控制风格 | 可靠 | **不可靠**（A 任务负向 prompt 被归类到木刻风格） |
| 批量生成多种风格统一 | 未验证 | **不可靠**（D 任务三张并列出三种风格） |
| Agent 一次生成 spritesheet | 假设可行 | **会作弊**（agent 偷写 python 脚本把单帧拼贴） |

旧日志判断"gpt-image-2 不支持透明"的根因：当时的 prompt 是隐式表述透明，被 codex 内部 taxonomy 归类成 `product-mockup`，触发 3D 实物建模风格，于是误判模型能力。

总 token 成本：约 280k（A 30k + B 33k + C 49k + D 70k + 早期测试 98k）。

## 落地调整

### 1. `prepare-spritesheet-sprite.mjs` 双路径 fallback

新增 `--mode auto|transparent|chroma-key`，默认 `auto`。

决策树：

```
生图输出 spritesheet.png
  ↓
decodePng + analyzeTransparency
  ├─ hasUsableAlpha (transparentRatio>5% 且 edgeRatio>50%)
  │    → mode=transparent，直接拆帧，不调用 applyChromaKey
  └─ 否
       → mode=chroma-key，跑原 applyChromaKey 路径
            ↓ 抠不出
            └─ fail-fast，不重试
  ↓
detectIdenticalCells
  ├─ 全唯一 → 写盘
  └─ 有重复 → fail（除非 --allow-identical-frames）
```

- `--mode transparent` 强制要真 alpha，不达标 fail-fast，错误信息明确写 "Do NOT retry"。
- `--mode chroma-key` 保留旧路径不动，已通过 official 的 yi 资产不受影响。
- 反作弊：相邻 cell 像素完全一致直接 fail，堵 agent 用 python 拼图的偷工路径。
- manifest 增加 `generationMode` 和 `sourceTransparency` 字段，下游 validator 能追溯 sprite 来源。

### 2. Prompt 模板 `cutout-sequence-prompt.md` 重写

- 主路径段落改为透明 PNG：明确写 `Save the result as a transparent PNG with an alpha channel (RGBA)`、`background must be fully transparent (alpha = 0)`、`no backdrop / no floor / no shadow / no halo`。
- Fallback 段落保留 chroma-key prompt，标注"仅当透明输出失败时切换一次"。
- 增加 generation discipline 段：单字单动作、不允许脚本拼接、prompt 失败只切一次不循环重试。

### 3. AGENTS.md / README.md 加 hard stop

新增 3 条 stop 规则：

- spritesheet 必须来自一次 image-generation call，不允许脚本拼贴。
- 透明 / chroma-key 失败时只切换一次，不重复同 prompt 重试。
- 一次 call = 一个 `(character, actor, action)` 组合，不允许批量。

### 4. 知识库同步

- `06-素材资源/Unit-01素材与生图生产规范.md`：修正"透明物件 cutout"段，主路径走透明 PNG，chroma-key 降级为 fallback。
- `05-技术文档/HyperFrames多帧动画Agent流水线方案.md`：新增"2026-05-15 生图能力纠偏与 fallback 机制"段，记录调研结论和决策树。
- `tools/recognition-video/schemas/sprite-manifest.schema.json`：放开 `generationMode` 和 `sourceTransparency` 字段。

## Smoke 验证

不跑端到端生图 smoke（避免烧 token），用本地构造 + 现有资产验证 4 条路径：

| Smoke | 输入 | 模式 | 期望 | 结果 |
|---|---|---|---|---|
| A | 构造 RGBA spritesheet | `--mode auto` | 检测到 alpha → transparent 路径 | ✅ auto-detected transparent alpha (ratio=0.687, edge=1.000) |
| B | 现有 chroma-key RGB sheet（sun rise-glow） | `--mode auto` | 无 alpha → fallback chroma-key | ✅ no usable alpha → chroma-key mode |
| C | 现有 chroma-key RGB sheet | `--mode transparent` | fail-fast | ✅ 明确报"Do NOT retry"并退出 |
| D | 构造重复帧 RGBA sheet | `--mode auto` | 反作弊拦截 | ✅ Detected 1 identical frame pair(s): 0<->1 |

兼容性检查：

- `npm run video:check-sprite-example` 通过（旧 example manifest 不受 schema 改动影响）。
- `node --check prepare-spritesheet-sprite.mjs` 通过。

## 关键决策

1. **主路径切透明，旧路径保留**。chroma-key 不是历史包袱，是合理的兜底——不删，只降级。
2. **失败一次就停，不在脚本里重试**。这是用户明确要求的"不浪费 token"原则的代码化。把决策权交回 agent 和产品 review。
3. **反作弊放在脚本而不是 AGENTS.md**。文档约束 agent 行为时容易被忽视，把 `detectIdenticalCells` 写进脚本能直接挡住偷工的产物。
4. **manifest 加 generationMode**。下游 validator 和后续审查能识别 sprite 是真透明还是抠色出来的，避免历史包袱混淆。
5. **不重新生成已通过的 official 资产**。`yi-fresh-horizon-sync-v4` 和 `yi-gpt-image-2-official-v1` 的 chroma-key sprite 都继续有效。

## 接手提示

下次产新字 spritesheet：

1. 先读 `tools/recognition-video/templates/prompts/cutout-sequence-prompt.md`，按主路径段落写 prompt。
2. 一次 image-generation call 只产 `(character, actor, action)` 一个组合。
3. 落盘后跑 `npm run video:prepare-spritesheet -- --mode auto ...`，让脚本自己决定走透明还是 chroma-key。
4. 不要重试。脚本 fail 了直接看错误信息，修 prompt 或换路径，不要循环。
5. 透明失败时切 chroma-key prompt 一次；chroma-key 也失败时停下来报告，不在 agent 里硬扛。
