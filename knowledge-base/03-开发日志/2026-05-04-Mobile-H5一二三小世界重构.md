# 2026-05-04 Mobile H5 一二三小世界重构

## 背景

用户指出上一版 H5 虽然能跑通，但如果换位成投资人、孩子或家长，仍然不够让人愿意投钱、喜欢或付费。结论是当前产品不能继续以“能演示”为验收标准，必须回到产品第一性体验：孩子在暖阳绘本小世界里发现汉字，家长能看到明确的学习证据。

## 本轮关键决策

- 不再平均优化 20 个字，先把 `一 / 二 / 三` 做成 vertical slice 样板。
- 把“认字页”从视频框 + 字卡 + 组词卡改成“阳光小世界”：生活物、字形、声音和可点击发现都在同一场景里。
- 把“练习题”从看图选字改成找字游戏：孩子先辨认横线数量，再把字收进宝库。
- 把“家长中心”从数据面板补强为证据面板：说明孩子刚才完成了“生活里发现 -> 字形里确认 -> 用手画出来”的闭环。
- 修正 `二` 的语文表达，移除 `二只`，避免家长信任受损。

## 当前实现

- `src/shared/unit-01.js`
  - `二` 的 `phrase` 改为 `两个的二`。
  - `二` 的组词改为 `两个 / 二月 / 第二`。
- `src/clients/mobile-h5/app.js`
  - 新增 `storyWorlds` 数据，定义 `一 / 二 / 三` 的场景、老师引导、可点击发现、练习提示和家长证据。
  - 单元页新增“阳光小院样板闭环”入口，突出 `一 / 二 / 三`。
  - 认字页对样板字走 storybook 结构，点击发现 chip 会播读并更新老师提示。
  - 写字页改为“画进小路”的语气，按钮从 `跳过` 改为 `我画好了`。
  - 练习页对样板字走 storybook 找字游戏。
  - 家长中心新增“今天真正学到什么”证据卡。
- `src/clients/mobile-h5/styles.css`
  - 新增小世界、样板字卡、找字游戏、家长证据卡等样式。

## 验收重点

- 孩子是否一眼知道现在要做什么。
- 认字页是否更像小世界，而不是学习软件表单。
- `一 / 二 / 三` 是否有明显区别，又属于同一片暖阳世界。
- 家长中心是否能解释“为什么这不是随便点点”。
- in-app browser 中关键路径无白屏、无控制台 error/warn、文本不挤压。

## 已验证

- `node --check src/clients/mobile-h5/app.js`：通过。
- `node --check src/shared/unit-01.js`：通过。
- `node --check src/clients/mobile-h5/server.mjs`：通过。
- `node --check src/clients/mobile-h5/sw.js`：通过。
- in-app browser 已跑：Home -> Unit -> `二` 小世界认字 -> 点击发现 chip -> 写字页 -> 找字游戏 -> 正确反馈 -> 自动进入 `三` 小世界 -> 家长中心证据页。
- 控制台 `error/warn` 为空。

## 验证中发现并修正

- 单元页同时出现样板卡和 20 字网格，导致 `二 er` 有两个可点击入口；已移除首屏 20 字网格，避免孩子认知负担和无障碍歧义。
- `二` 的底层大字和笔画动画叠加后像多出一条线；已将底层字形降成淡纸纹，让真实笔画成为焦点。
- 家长页累计时长超过 15 分钟时仍像普通进度说明；已改成主动建议休息。

## 用户复核反馈

- 用户在 in-app browser 复看后指出：当前 UI 视觉上仍然“糊一块”，元素、层级、背景、字形和卡片没有真正拉开，不能作为合格界面继续推进。
- 这说明本轮重构只完成了产品结构方向切换，没有完成视觉层级和界面质感重建；下一轮不能只验证 DOM、路由和 console，必须以截图观感为第一验收标准。
- 下一 session 继续动刀时，先做视觉瘦身和层级重排：减少同屏信息量，拉开主场景/教师提示/操作区，弱化卡片堆叠，避免字形、笔画、背景、装饰互相抢焦点。

## 待继续

- 继续用 in-app browser 实测视觉和交互，根据截图修第二轮细节。
- 若样板体验成立，再为 `二 / 三` 设计正式 HyperFrames 分镜；不要急着批量替换 20 个字。
