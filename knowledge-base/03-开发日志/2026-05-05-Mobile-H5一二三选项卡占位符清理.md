# 2026-05-05 Mobile H5 一二三选项卡占位符清理

## 背景

上一轮“一二三视觉重排”虽然已经把练习页从普通答案卡改成了 storybook 找字游戏，但用户在 in-app browser 截图中继续指出：答案区那种 `一 / 二 / 三` 横线式图形在 UI 上非常丑，像占位符，而不是儿童产品里真实可点、可理解、可相信的物件。

这次反馈很关键：`一 / 二 / 三` 本身是横线字，不能把字形笔画直接当作答案卡图标反复堆在界面里。否则孩子看到的是抽象线段，家长看到的是廉价占位图。

## 本轮完成

- `src/clients/mobile-h5/app.js`
  - 新增 `storyChoiceMeta`，为 `一 / 二 / 三` 分别绑定 `小路 / 木板 / 小山` 和 `1 条 / 2 块 / 3 座` 数量徽章。
  - 单元页 hero 标题从 `一 二 三` 改为 `阳光三小步`，避免第一屏继续露出机械排字。
  - 单元页三张样板入口卡移除大号 `一 / 二 / 三` 字形，改为 `storySceneMarkup()` 输出微场景。
  - 练习页 `renderStoryAnswerCard()` 不再渲染裸笔画预览和大字，改成“小场景 + 数量徽章 + 物件名称”。
- `src/clients/mobile-h5/styles.css`
  - 新增 `.mini-story-scene` 系列样式：暖阳、草地、小路、木板、小山三种微场景。
  - 调整 `.story-answer` 高度、内距和 caption 层级，避免全局 `.answer-card span` 样式误伤新结构。
  - 收紧单元 hero 标题尺寸，让它像绘本章节标题，而不是字形展示板。

## 视觉验收结论

- 单元页底部三张卡现在是 `阳光小院 / 花田边 / 小山坡` 的入口，每张都有一个小场景，不再是大字卡。
- 练习页 `哪个是三？` 的答案区现在显示 `木板 / 小山 / 小路`，每张卡有数量徽章，孩子能按物件理解数量差异。
- 视觉上仍保留 `一 / 二 / 三` 的教学关系，但不再把横线本体当作 UI 装饰反复出现。

## 研发笔记

- **横线字不能裸用为卡片图标**：`一 / 二 / 三` 的字形太简单，直接放进按钮里会像骨架屏、占位符或调试线段。儿童识字 UI 需要先用生活物承载含义，再把字形作为认知归纳出现。
- **答案卡应该像可点物件，不像练习纸**：P05 找字游戏的选项应优先是“小路、木板、小山”这类厚实物件；字形和笔画只在主问题区或书写区承担教学任务。
- **数量关系要藏在场景里，也要显式给家长看**：微场景让孩子直观看见一条、两块、三座；数量徽章让家长/成人快速理解这不是随意插画，而是教学线索。
- **不要用“几根线 + 标签”冒充插画**：这会把产品拉回廉价 AI 模板感。后续横线类字、简单笔画字都要避免用裸笔画填卡片。

## 后续接手约束

- 后续继续改 `一 / 二 / 三` 时，不要把答案卡回退成裸横线、大号汉字卡或“几条彩色线 + 标签”的结构。
- 若要继续提升质感，优先替换为更完整的绘本小插画或 CSS 小物件，而不是增加边框、阴影和装饰线。
- 其他简单字也要警惕同类问题：字形越简单，越不能直接当 UI icon，需要先找到生活化承载物。
