# 2026-04-30 Mobile H5 首屏进度状态纠偏

## 背景

用户指出：前面严格按照视觉稿还原 P01 长卷没有问题，但 Mobile H5 是真实体验，不能一打开就表现得像前面几关已经玩过。

这次问题的本质不是视觉还原错误，而是把视觉稿里的“取景状态 / 示例状态”误当成了产品真实初始进度。

## 问题

`src/clients/mobile-h5/app.js` 的 `renderHome()` 里硬编码了多个 `journey-node--done`：

- 第 1 组、第 2 组、第 3 组默认显示为完成/已点亮态。
- 小星宝库节点被放在地图路径中，进一步强化“前面已经玩过”的误读。
- P01 默认取景固定在视觉稿“当前关居中”的中段，而不是根据真实进度定位。
- `locked` 点击逻辑只要 `learnedCount() > 0` 就进入付费页，导致只学 1 个字也能触发第二单元引导。

## 决策

Mobile H5 的初始状态必须以真实产品体验为准：

1. 视觉稿只作为画面构图和状态样式参考，不代表真实用户默认进度。
2. 首次进入时，学习地图必须从 `0` 进度开始：第一组可开始，后续组锁定。
3. 首页默认取景必须跟随真实当前进度：
   - `0` 进度：聚焦底部起点 / 第 1 组。
   - 学到某组：聚焦当前组。
   - Unit-01 完成：聚焦第二单元入口。
4. 第二单元 / 付费引导只有在 Unit-01 全部完成后才允许进入。
5. 不通过更换 `localStorage` key 来“清缓存式修复”，避免误清真实用户进度；旧数据应兼容迁移。

## 本轮改动

### `src/clients/mobile-h5/app.js`

- 新增 `createDefaultProgress()` 和 `schemaVersion`，保留原 `STORAGE_KEY = starlight-literacy-mobile-h5-v1`。
- `loadProgress()` 对旧进度做兼容迁移，不清掉已有真实学习进度。
- 新增进度派生函数：
  - `isUnitComplete()`
  - `groupLearnedCount()`
  - `isGroupComplete()`
  - `activeHomeGroup()`
  - `homeGroupStatus()`
- P01 首页节点改为进度驱动：
  - 第 1/2/3 组按 `active / done / locked` 渲染。
  - 第 4 组只有前面完成后才显示为当前大节点，否则锁定。
  - 第二单元入口只有 Unit-01 完成后变为可进入。
- 默认地图取景改为进度驱动，不再固定 `MAP_FOCUS_Y = 846`。
- 锁定节点点击从 `learnedCount() > 0` 改为 `isUnitComplete()`。

### `src/clients/mobile-h5/styles.css`

- 补齐 `journey-node--active` 样式，保证首次进入的“从这里开始”节点有完整视觉表现。
- 新增 `journey-node--next-ready`，Unit-01 完成后第二单元入口才变为可继续状态。

## 接手约束

- 后续做 H5 或小程序实现时，必须区分：
  - **视觉稿状态**：用于看构图、层级、色彩和组件样式。
  - **产品运行状态**：必须由真实进度、真实权限、真实流程驱动。
- 不要因为视觉稿某个节点是“已通关 / 当前关 / 锁态”就把该状态硬编码成所有用户默认值。
- 不要用更换 `localStorage` key、清空缓存、重置 schema 的方式掩盖状态 bug；除非确实是不可兼容的数据结构变更。
- P01 长卷仍然必须保留 `390×1800` 独立画卷 + 自定义拖动，不回退到浏览器普通滚动。
