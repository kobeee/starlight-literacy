# Claude mh5v2 产品落地方法论

> 本文不是给某个模型背书，而是把 `starlight-mh5v2` 这棵 worktree 相对 `codex/mobile-h5-v2` 做对的产品思维抽出来，作为后续 H5 / 小程序 / Agent 协作的复用准则。

## 结论

Claude 这次做得更好的地方，不是页面更多，也不是 CSS 更长，而是它把产品定稿、竞品红线和教学护城河翻译成了**不可绕过的系统结构**。

Codex 版本的问题也不是单纯“少写代码”，而是把产品合同写成了可见文案，却没有变成真实约束：写字可以直接点过，跟读可以不录音就过，字源和图卡是泛化插画，工程自检通过但产品不成立。

## 核心方法

### 1. 先把产品红线变成系统边界

Claude 的实现从 `CLAUDE.md`、[[竞品洪恩用户反馈校准]]、[[砍cinematic后执行方案]] 出发，把红线落到数据 schema、页面路由和状态机里：

- 写字真判定 → `hanzi-writer` 本地 vendor + 字数据 + `quiz()`。
- 跟读必须录音对比 → `MediaRecorder` + teacher/user 双波形 + CTA 解锁。
- 付费透明 → FREE / ¥9.9 / ¥199 三 SKU 明确建模。
- 退款宽松 → `requested → completed` 的 2 步状态机。
- 邀请合规 → 只允许单元解锁 / 学伴券，累计上限 10 次。

原则：**红线不能只出现在页面文案里，必须出现在代码边界里。**

### 2. 五大模块不是页面名，是产品承诺

`P03 / P04 / P05a / P05 / P09-P11` 在 Claude 版本里是独立页面和模块，而不是一个大 `app.js` 里几段 HTML。这个拆法让每个模块都能对应一个产品承诺：

| 模块 | 产品承诺 | 结构落点 |
|---|---|---|
| P03 字源 | 真象形 / 真会意，不直映法 | `data/etymology-assets.js` + 字源字段校验 |
| P04 写字 | 不乱画也判对 | `modules/hanzi.js` + `P04-write.js` |
| P05a 跟读 | 必须录音并对比 | `modules/follow-record.js` + `P05a-listen.js` |
| P05 图卡 | 看真实事物认字 | `imagecard-assets.js` 明确 `needsRealAsset=true` |
| P09-P11 商业 | 透明付费、宽松退款、邀请克制 | `commerce.js` 状态机 |

原则：**模块拆分要服务产品责任，不是为了“代码好看”。**

### 3. 护城河必须不可绕过

Claude 版本里，P04 / P05a / P05 的主 CTA 初始都是 disabled，只有真实动作完成后才解锁。Codex 版本的 `finish-write` / `finish-read` 是典型反例：按钮一开始就能点，等于把护城河做成了舞台布景。

验收标准：

- P04：未完成 `hanzi-writer.quiz()` 前，不能进入跟读。
- P05a：没有录音、没有用户波形前，不能进入图卡。
- P05：未选中正确答案，不能进入下一字；错多了可以老师放过，但要有学习回放。

原则：**零挫败可以自动放过，但不能无行为通过。**

### 4. 零挫败不是假判定

好的零挫败是“先真实尝试，再温柔降级”。Claude 的 P04 / P05a / P05 都遵循这个思路：

- 第一次错：温和提示。
- 多次错：给更明显的 hint 或回放。
- 仍卡住：老师帮忙过，仍给星。

这和“乱画也算对”“没录音也算跟读”完全不同。后者会直接触犯洪恩反馈里最致命的家长不信任点。

原则：**孩子不被惩罚，但系统不能欺骗家长。**

### 5. 占位要诚实标记，不把假资产说成成品

Claude 版本仍有明显不足：P03 的甲骨/金文/篆文图片缺失，P05 图卡还是 emoji 占位。但它把这些占位显式写进 `onerror fallback` 和 `needsRealAsset=true`，没有把占位资产包装成最终设计。

原则：**占位可以存在，但必须能被后续生产流程识别和替换。**

### 6. 视觉方向要服务“晒暖绘本小世界”

Claude 版本的优势是统一用了暖米、蜂蜜金、暖深棕、低饱和辅助色，且避免紫蓝渐变、霓虹、暗底 glow。它的问题是仍有较多卡片式移动网页痕迹，离 `.impeccable.md` 要求的“每一屏像一个小世界”还有距离。

后续视觉判断：

- 首页 / 字源 / 图卡要更像绘本场景，不只是卡片列表。
- 核心任务要一屏一件事，不要把家长信息密度带进孩子页。
- 图卡必须是真实事物或高质量插画，不能用目标字本身替代画面。

原则：**暖彩不是浅色 UI，绘本感不是卡片套插画。**

### 7. 自检脚本只能证明“没坏”，不能证明“对了”

本次 Codex 版本也通过了 `npm run check:h5:v2`，但 Chrome 点击流证明产品核心不成立。Claude 版本也通过检查，同时在真实页面里验证出 CTA 确实不可绕过。

后续 H5 验收至少分三层：

1. 静态检查：语法、路由、缓存、禁用 OS TTS。
2. 浏览器实测：Chrome 真页面逐步点击，不看截图自嗨。
3. 产品合同检查：P04 / 跟读 / 付费 / 退款 / 邀请逐项对红线。

原则：**validator pass 不是 product pass。**

## 不要盲抄 Claude 的部分

- P03 真字源资产还没完成，fallback 成现代字只能算结构先行。
- P05 图卡还是 emoji 占位，不能进入正式验收。
- 视觉仍偏“卡片化 H5”，还需要向绘本场景化推进。
- Unit-02~87 仍是内容生产空位，不等于 1300 字内容已完成。
- 真机麦克风、手指描红、低端机性能仍未闭环。

## 后续 Agent 执行准则

1. 开工前先读产品权威源，不从 UI 开始。
2. 先定义不可绕过的学习动作，再做页面。
3. 所有红线要落到 schema / 状态机 / 禁用态 / 验收脚本。
4. 所有占位资产必须显式标记，不允许伪装成成品。
5. 每次 H5 review 必须用真实浏览器跑主链路。
6. 如存在并行 worktree，默认对照最强实现，不保护自己的版本。
