## 0. 这次重审是怎么触发的

2026-05-29 用户连续三轮指出同一个根：

1. **第一轮**：「认字那里…这小孩子都不知道咋认」+「这一版 app 字好多」。
2. **第二轮**：澄清——「认字」指的是**一开始介绍汉字那里，一堆的字，咋学呢**；「字好多」指的是**界面都是字**。
3. **第三轮**：「重新审视产品设计和理念，幼龄儿童什么样的方式最容易最有效让孩子认得汉字？」→ 拍板按本文新流程走。

**贯穿的病根一句话**：这版 app 是按"用户认识字"做的，可用户是**还不识字的 3-6 岁孩子**——这恰恰是认字 app 存在的全部理由。每一屏都在漏这个假设（介绍页是文字散文、认字页让孩子在一堆相似字里挑、界面到处是给家长看的营销文案）。

## 1. 第一性原理：3-6 岁孩子是怎么把一个字记住的

幼儿（皮亚杰前运算阶段）认字有四条硬规律，是本方案的全部地基：

1. **音和义他已经有了，缺的只是"形"。** 4 岁孩子会说"太阳"、懂太阳是什么（音 + 义齐全），唯一不认识的是「日」这个**符号**。认字的本质 = **把一个新符号(形)挂到他脑里已有的音和义上**，不是"教他理解这个字"。
2. **幼儿认字是整体图形记忆，不是分析。** 他把「日」当一张图/一个 logo 整体记住（像认人脸、认麦当劳标志），不拆笔画、不推来历。"能认出来"远早于"会写、懂为什么"。
3. **记住靠多通道同时绑 + 高频多情境复现，不靠单次讲得深。** 图+音+形三通道同时进、再在不同地方反复遇见 N 次——这才是留下记忆的机制。讲解深度对这个年龄反而无效。
4. **理解"字的来历/本义"是更高阶认知，对 3-6 岁不是地基，是天花板。**

## 2. 核心错位诊断：把"护城河"当成了"主教学法"

两件不同的事被旧设计混成了一个环节（P03 字源讲解）：

| | 护城河（字源真讲） | 主教学法（让孩子记住） |
|---|---|---|
| 服务对象 | **高知家长**（"这家不像洪恩瞎编"） | **孩子** |
| 洪恩反馈定位 | §3 line 390「普通用户**不感知**，是质量护城河」 | §3.1 家长要的是"真学会了" |
| 适用范围 | 仅真象形字（约占字库 15%） | 全字库 1300 字 |
| 正确形态 | 象形字的收尾彩蛋 + 家长可见证据 | 图音字一体认读 + 复现 |

**两个致命问题**：

- **字源撑不起 1300 字**：真象形、能"实物→古字"直观演化的字也就一两百个（日月山水火木…）。绝大多数是形声字、抽象指事字（"的""和""我""上""下"怎么象形？）。给每个字硬配字源，**必然滑向洪恩被骂的"直映法牵强"——正是红线 §7.3 要防的东西**。把只对 15% 字成立的方法当 100% 字的地基，是方向性错位。
- **护城河的活（说服家长）和主教学法的活（让孩子记住）被同一个环节硬扛**，做成一整页中文散文，结果孩子读不了、家长也未必翻到，两头落空。

## 3. 新主教学法：学一个字走五步（顺序即设计）

> 通用于全部 1300 字。第 6 步「字源彩蛋」仅象形字才有（见 §4）。

| 步 | 名称 | 孩子在做什么 | 画面 | 声音 | 交互 | 文字 |
|---|---|---|---|---|---|---|
| **1** | **认读绑定** | 把新符号挂到已有的音义上 | 满屏一张**生动实物图/场景**(太阳/嘴/树)，字**浮现叠加在图上** | 进页**自动**播老师念音（女老师成熟音，baked）；可重播 | 点图/点字 = 重播音 | 仅一个大字 + 拼音；**无说明文字** |
| **2** | **动手指认** | 把字当整体图，主动认出来 | 2-4 个候选（**配图**，不是一堆相似字）/ 拖字到对应图 / 场景里找字 | 点对即时正反馈音 + 念音；点错温柔提示音 | 点选 / 拖拽 / 找一找 | 题干**不印答案字**；尽量用图+语音出题 |
| **3** | **跟读** | 把字说出来 | 老师口型/波形 | 老师标准音 + 孩子录音回放 | 录音 → 双波形对比（不接 ASR，保留现有） | 极少 |
| **4** | **写** | 描红，建立笔顺肌肉记忆 | 田字格 + 笔顺演示 | 描红音效 | 手指描红（保留现有 StrokeJudge 真判定 + 零挫败容差） | 极少 |
| **5** | **复现** | 在新情境再遇见这个字 | 本课结尾、复习页、小组练习、下一课句子里再次出现 | 念音 | 再认 / 再选 | 极少 |

**关键变化（对比旧流程 P03字源讲解→P04写→P05练）**：

- **打头的不再是"讲解"，是"认读绑定"**：先让孩子在图+音里**认得**字，而不是先读一段他读不懂的字源散文。
- **第 2 步才是真正的"看图认字"**：候选项配**真实图**、题干**不印答案字**、干扰项**不再全用形近字**（旧实现学「一」时四选项是 一/二/三/土 全横线，既挫败又什么都没测出来 → 废弃）。
- **字源被移出主路径**（见 §4）。

## 4. 字源彩蛋规则：仅象形字、放在认读之后、一身二用

### 4.1 触发规则

- **只有"真象形字"**才在第 5/6 步追加一个"原来这个字是这样来的"小惊喜：**实物图 → 甲骨 → 今字**的形变（静态插画 + CSS/SwiftUI 微动效 + 老师一句话旁白）。
- **触发时机**：孩子**已经认得字之后**（不在最前面、不打断认读）。
- **一身二用**：给孩子加一个记忆锚点；给家长看"我们是真象形不是瞎编"（护城河，家长中心也可回看）。
- **非象形字一律不做字源环节**——硬讲就是直映法牵强，坚决不做。

### 4.2 "哪些字算象形"的判定标准（防直映法的硬线）

**判定标准**：该字的甲骨文/金文是否**"画一个具体可见之物"（六书的"象形"类，pictograph）**。是 → 可做字源彩蛋；指事/会意/形声一律不做。

Unit-01 的 20 字按此分类（作为标准的落地范例）：

| 类别 | 字 | 字源彩蛋 |
|---|---|---|
| **象形（画物，做彩蛋）** | 人 口 手 日 月 山 水 火 木 目 耳 田（12 字） | ✅ 实物→甲骨→今字形变 |
| **象形边界（轻量可做）** | 大（正面张臂的人）、土（地上土堆）（2 字） | ⚠️ 弱形变，做轻量版或并入复习 |
| **指事/抽象（不做彩蛋）** | 一 二 三 上 下 小（6 字） | ❌ 抽象符号约定，无物可画；走"认读+复现"，不强讲来历 |

→ 即便在"最象形"的 Unit-01，也有 6/20 不该走字源。放大到 1300 字，象形占比更低，**这条线决定了字源只能是彩蛋、不能是地基**。

## 5. 界面铁律：给不识字的孩子，就不能靠字

- **图为主、声音自动播为主，文字几乎清零**（孩子侧每一屏"不识字也能玩得动"）。
- **所有写给家长的话**（价格、教学法黑话"象形为主·真象形真会意·不直映法"、规模对比"洪恩¥388 vs 我们¥199"、1300 字吆喝）**全部下沉到家长中心**，不出现在孩子的学习屏/首页。
- **首页不摊字墙**：不一次性铺 20 字网格当生字表；回到"当前一字/一关放大、其余收进路径"的旅程感（呼应 USER_FLOW 原本的"学习地图"定位、[[project_p01_dual_audience|P01 双受众分层]]——孩子要清爽视窗、家长才看全景规模，用分层不用折中）。
- **语音是主通道不是装饰**：进页自动念，不是角落一个可点可不点的小喇叭。

## 6. 对既有定稿的显式 diff（遵循砍cinematic §D5 三选一标明）

**【替换】** 砍cinematic后执行方案 §2.3「模块 3 · P03 字源页」的定位：
- 旧：`P03 = 每字必经的字源讲解页（静态 SVG + CSS 微动效 + baked 旁白）`
- 新：`字源 = 仅象形字的收尾彩蛋（实物→甲骨→今字形变 + 微动效 + baked 旁白）；非象形字无字源环节。学一个字的主路径改为"图音字一体认读 + 动手指认 + 跟读 + 写 + 复现"五步。`

**【替换】** 学一个字的流程序列：
- 旧（USER_FLOW 学习循环）：`P03 认(字源插画) → P04 写 → P05 练`
- 新：`认读绑定(图音字) → 动手指认(真看图认字) → 跟读 → 写 → 复现；象形字在认读后追加字源彩蛋`

**【新增】** 字源彩蛋的"象形判定标准"（§4.2）——六书象形类才做，指事/会意/形声不做，作为防直映法（红线 §7.3）的可验证硬线。

**【替换·2026-06-02】** §3 step2「动手指认」的**默认交互 pattern**（孩子视角走查发现旧实现空转，详见 [[../03-开发日志/2026-06-02-Unit01孩子视角走查与待解问题]] 母题B）：
- 旧实现（落地版，非本文原意）：题干=语音、候选=**实物图+字** → 孩子靠「音→图」连连看，全程不看汉字，「字形」这一环空转（与 1 岁就会的看图能力无异）。
- 新：采用本文 step2 本就列出的「**拖字到对应图 / 音挑字**」pattern——**题干=实物图(义)+老师念音；候选=纯汉字**，孩子必须盯字形本身挑出来，才真练到「形」。
- **这不是翻案**：step2 原文已列「点配图候选 / 拖字到对应图 / 场景里找字」三种，旧实现只是挑了最弱的"点配图候选"；本次切到更强的"音挑字"。§1 第一性「缺的只是形」要求这一步必须有一次靠字形做判断的动作。
- 配套：① 干扰项「混搭」=默认 1 形近逼看字形细节 + 其余非形近拉梯度；零挫败时撤形近名额降难度（`EtymologyAssets.buildOptions(_:relax:)`）。② 认字测试页顶栏不挂答案字（`StageTopBar.revealChar=false`），堵送分漏洞。落地见 `P05ImageCardView.swift`，`OptionBuilderTests` 5 例锁住策略。

**【替换·2026-06-03】** §3 step1「认读绑定」的字形呈现方式（护城河审计「四刀序」第二刀，详见 [[../03-开发日志/2026-06-03-第二刀音形绑定落地]]）：
- 旧实现：字形是**静态大字** `Text(char.char)`，念音与字形各自独立，没把孩子注意力从已有的音牵到新符号的形上。
- 新：进页/点卡片**自动念音时，字形随音逐笔点亮**（hanzi-writer 真字形，像老师写字一样描出来，念完整字成型停留）——音→形绑定（调研 §二3 Duolingo ABC）。落地 `StrokeRevealGlyph`（`SharedComponents.swift`，复用 `HanziStroke` + `DemoWriterView` 的 trace pattern）+ `AudioService.play` 回传时长对齐节奏。
- **这不是翻案**：step1 原文就写「字**浮现**叠加在图上」+「进页自动播老师念音（主通道）」；本刀把「浮现」从静态做成「随音逐笔点亮」，强化 §1 第一性「缺的只是形」要求的音→形绑定。`StrokeDataTests` 钉住 20 字 json 齐（缺则回退静态字、丢价值）。

**【新增】** 界面去文字化铁律（§5）——家长向文案全部下沉家长中心。

**【保留·不动】**
- P04 写字真判定（hanzi-writer / StrokeJudge + 零挫败容差）= 护城河 #1。
- 跟读 WaveSurfer 双波形、不接 ASR = 护城河 #2。
- 付费三层（免费 Unit-01 / ¥9.9 / ¥199 一期）+ 双向邀请 + 退款红线。
- 字源真讲红线 §7.3（做的那部分仍必须真象形、可验证）。
- baked audio 架构（只播 mp3、禁 OS TTS）。
- 不打视频军备竞赛（红线 §7.8）：字源彩蛋用静态插画 + 微动效，**不做 mp4 视频**（理由：ROI 数学 + 治标不治本，详见 2026-05-29 笔记）。
