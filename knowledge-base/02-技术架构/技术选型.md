# 技术选型决策

## 总体方案

> 2026-04-29 调整：因微信小程序个人主体接入微信支付受限，且 iOS 首发存在账号、审核和 IAP 成本，当前阶段先做 Mobile H5 验证版。小程序原生方案仍作为后续正式端候选，不再是当前首发实现。

| 层面 | 选型 | 理由 |
|------|------|------|
| 当前前端 | Mobile H5（原生 ES module + CSS） | 最快验证市场，不依赖小程序主体和 iOS 审核 |
| 当前渲染 | 浏览器 DOM / CSS / SVG / Canvas | 足够验证认字、书写、练习、家长付费意向 |
| 当前后端 | 暂无实时后端 | MVP 用 `localStorage` 记录学习进度和付费意向 |
| 当前支付 | 付费意向记录 | 暂不接真实支付，先验证 Unit-02 9.9 意愿 |
| 后续小程序前端 | 微信小程序原生开发 | 性能最优，深度使用微信能力 |
| 后续小程序渲染 | Skyline | 同步光栅化、Worklet 动画、手势系统 |
| 后续后端 | 自建 API / 微信云开发待定 | 取决于 H5、小程序、iOS 的最终组合 |
| 后续文件存储 | CDN / 云存储待定 | 插画、音频、题库需要跨端分发 |
| AI 内容生成 | Claude Opus 4.6 + Nano banana pro | 数据配置 + 插画生成 |
| 语音合成 | 待定（AI TTS） | 认读语音生成 |

## Mobile H5 验证版

当前落地路径：

```text
src/
├── clients/
│   ├── mobile-h5/
│   └── miniprogram/
├── backend/
└── shared/
```

Mobile H5 关键约束：
- 只支持手机竖屏体验，不做桌面 Web 产品。
- 桌面浏览器只作为调试容器，实际 UI 以移动端视觉稿为准。
- P01 首页必须是长轴画卷自定义拖动，不使用浏览器 body 滚动或固定 CSS 背景图替代。
- 现阶段不接真实支付，不做账号体系。
- 使用共享内容层 `src/shared/unit-01.js`，未来小程序/iOS 复用内容模型。
- 认字动画先用 CSS/SVG 原生实现；Hyperframe / Remotion 若确认可用，再替换为正式动画资产。
- 本地开发服务：`npm run dev:h5`。
- 静态检查：`npm run check:h5`。

P01 首页资源与交互约定：
- 设计基准：`design.pen` 中 `9wPMd / IF6la`。
- 画卷坐标系：`390×1800`，按手机容器宽度缩放，首屏为取景窗口。
- 正式资源组合：`p01-bg-redraw-road-centered-20260426.png`、`p01-pastoral-overlay-20260426.png`、`p01-animal-edge-overlay-20260426.png`。
- 禁止回退：不要恢复已废弃的 `p01-start-house-*` / `p01-start-home-entrance-*` 起点小房子方案；不要把 P01 首页实现成固定底图 + 普通页面滚动。

## 为什么选原生而非跨端框架？

> 本节是后续小程序正式端的技术判断。当前 H5 验证版不使用小程序原生，也不引入跨端框架。

### 对比结论（2026 年 4 月数据）

| 指标 | 原生 | Uni-app 5.0 | Taro 3.8 |
|------|------|------------|----------|
| 冷启动 | 680ms | 760ms | 820ms |
| 内存占用 | 145MB | 162MB | 185MB |
| Skyline 支持 | 完整原生 | 需适配 | 需适配 |
| 动画性能 | 最优 | 接近 | 一般 |

**决策理由**：
1. 当前聚焦微信小程序，原生性能最优
2. 儿童识字 App 对动画性能要求极高（书写、拖拽、粒子特效）
3. Skyline 的 Worklet 动画和手势系统在原生开发下体验最佳
4. 独立开发者项目，原生开发的学习曲线可接受
5. 未来若做 iOS/Android，各端 UI 独立实现即可（AI 辅助重写成本低），不需要跨端框架

## Skyline 渲染引擎关键特性

- **同步光栅化**：避免快速滚动白屏，对学习地图卷轴至关重要
- **Worklet 动画**：渲染线程同步运行，书写页逐笔反馈无延迟
- **手势系统**：原生拖拽、缩放支持，适合拖拽匹配题型
- **共享元素动画**：页面转场平滑
- **WXSS 预编译**：样式解析速度提升 5x

## 多端扩展策略

当前先用 Mobile H5 验证市场。若验证数据成立，再决定小程序、iOS 或双端推进。

**核心原则：不追求代码复用，共享资产和知识。**

| 跨端共享 | 各端独立 |
|---------|---------|
| 插画、音频等素材资源 | UI 界面和交互代码 |
| 字库、单元配置等 JSON 数据 | 平台原生动画和手势 |
| 系统设计文档（知识库） | 后端调用方式 |
| 业务规则描述（出题/评分逻辑） | 平台特有 API 调用 |

- 各端 UI 独立实现，AI 辅助重写成本远低于维护跨端框架的适配成本
- 代码分层（services/ + core/）是基本工程素养，保持代码整洁
- 素材和内容数据统一存放在 `src/shared/`、项目根目录 `assets/` 和 `data/`，所有端共用
