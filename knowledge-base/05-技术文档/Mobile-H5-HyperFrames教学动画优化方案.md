# Mobile H5 + HyperFrames 教学动画优化方案

## 背景

2026-05-02 讨论中重新对齐了 HyperFrames 在星光识字中的定位：

- 动画不是炫技、装饰或简单的“增强层”。
- 动画是 P03 认字页的教学媒介，用来吸引孩子注意力，并帮助孩子建立字形、字音、字义之间的记忆钩子。
- HyperFrames 不应该先验绑定为竖屏视频。视频比例、时长、画面结构必须服从产品形态和教学目标。
- 产品顶层设计在上，工具能力在下。不能从“有一个 HyperFrames 视频”反推页面结构。

因此，本轮将“把视频接进 H5”改成“把 P03 认字页重构为动画教学场景，再让 HyperFrames 产出适配这个场景的资产”。

## 2026-05-05 产品级重构修正

本方案中的 2026-05-03 / 2026-05-04 记录保留为历史过程，但执行优先级已被 [[01-产品设计/Unit-01产品级重构执行规划|Unit-01 产品级重构执行规划]] 修正：

- `一` 当前视频是救援样片，不再视为正式 baseline。
- 不再直接进入 `二 / 三` 视频迁移；先补完整 20 字课程字段和 H5 native micro-lesson。
- HyperFrames 视频退回增强层，必须服从统一内容模型和生图资产体系。
- 正式视频生产顺序改为：重做 `一` 标准样片 -> 通过后只做 `二 / 三 / 人 / 山 / 火` 代表字 -> 再决定是否扩到 20 字。
- 需要生图素材时，先按 [[06-素材资源/Unit-01素材与生图生产规范|Unit-01 素材与生图生产规范]] 生产可复用场景和物件，不能在视频目录临时生成风格不一致的散图。

## 顶层原则

### 1. 先教学，再动画

每个字先定义一个清楚的识字动作：

| 字 | 教学钩子 | 动画动作 |
|---|---|---|
| 一 | 平平一条线 | 地平线/横线慢慢出现，收束成“一” |
| 二 | 两条线 | 两层台阶或两片云并列出现 |
| 三 | 三条线 | 三座小山/三条横线按节奏排好 |
| 火 | 火苗向上跳 | 火苗跳动后高亮“火”的点撇形态 |
| 山 | 三峰站起来 | 山峰从地面长起，对应三竖结构 |
| 人 | 两笔支撑 | 两条路/两个人形成撇捺支撑 |

动画是否好，不看动得多不多，而看孩子能不能更快记住“这个字为什么长这样”。

### 2. HyperFrames 输出跟随页面容器

HyperFrames 可按不同产品场景输出多种比例：

- P03 认字舞台：横向或 16:10 容器，嵌在认字页上半屏。
- 关键字源小片段：必要时可做短暂沉浸式全屏。
- 宝库回顾：可输出 poster 或 1-2 秒轻 loop。
- 测验反馈：可输出局部小动图或短视频，不复用完整教学片。

当前 H5 优先使用 P03 横向教学舞台，不再默认竖屏整页。

### 3. 页面不是静态图加视频，而是认字小舞台

P03 推荐结构：

```text
顶部：返回 / 语音 / 认练写状态
中上：认字教学舞台（HyperFrames 视频优先，poster/fallback 次之）
中部：稳定大字 + 拼音 + 读音短语
中下：常见组词
底部：下一步 CTA
```

动画负责“理解”，稳定信息区负责“确认和复述”。两者不能互相抢戏，也不能重复成两套页面。

## 数据模型

在 `src/shared/unit-01.js` 的单字配置上增加可选字段：

```js
recognitionVideo: {
  src: "./assets/recognition/yi/yi-stage.mp4",
  poster: "./assets/recognition/yi/yi-stage-poster.png",
  finalFrame: "./assets/recognition/yi/yi-stage-final.png",
  width: 1280,
  height: 800,
  duration: 4.8,
  fps: 24,
  version: "2026-05-02-stage-v1",
  teachingCue: "一条平平的线，就是“一”。"
}
```

规则：

- `recognitionVideo` 是可选字段；没有视频的字必须继续走静态插画 + 原生轻动效 + TTS。
- `poster` 必须可作为首帧、弱网图和 reduced-motion 退路。
- `finalFrame` 必须是平静状态，不循环刺激孩子。
- `teachingCue` 是教学内容，不是功能说明。

## 播放策略

- 页面进入后先显示 poster 或静态插画。
- 视频可播放时淡入，播放一次后停在最后一帧。
- 点击认字舞台或语音按钮时，重播读音；如果视频可用，也允许重新播放教学动作。
- 自动播放失败、弱网、低端机、家长关闭动态效果时，退回 poster/静态图。
- 不循环播放，避免把注意力从汉字本身拉走。

## HyperFrames 模板调整

旧样片问题：

- `1080x1920` 竖屏完整页，和 P03 页面容器不一致。
- 视频内部包含“大字、拼音、组词、下一步”，与 H5 页面重复。
- 更像一页完整 App，而不是一个服务 P03 的教学舞台。

新模板方向：

- 输出 `1280x800` 的横向教学舞台。
- 时长约 `4.8s`，`24fps`。
- 画面结构为“场景轻入场 -> 字形关系高亮 -> 大字收束 -> 平静最终帧”。
- 不输出 App 顶栏和完整底部 CTA。
- 可保留少量动物/云朵做陪伴，但角色始终服务于字形记忆。

## 表现力升级方向（2026-05-03 补充）

2026-05-03 用户指出，当前“一笔横”版本比旧竖屏样片更聚焦，但仍偏单调，缺少儿童会记住的生动画面。后续 HyperFrames 不应局限于“线条描画 + 文字说明”，可以使用更接近绘本动画/逐帧动画的表达。

可选技术路径：

- 多张静态关键帧图片按时间轴切换，形成翻页式动画。
- Sprite sheet + CSS/GSAP `steps()`，用于角色张嘴、拿取、眨眼、跳动等短动作。
- 5-8 张关键帧插画 + 轻微位移/缩放/淡入，形成低刺激绘本动画。
- HTML/CSS 图形与插画关键帧混合：角色/物品用图片，字形收束用 CSS/GSAP 保持清晰。

但表现力必须受教学目标约束：

- 角色动作必须连接到字义或字形，不能只做可爱的独立剧情。
- 对“一”这类字，可以用“一个物品 / 一个动作 / 一条横线”串联数量和字形。
- 动画最后必须回到稳定汉字、pinyin 和短词语，final frame 可作为 poster/fallback。
- 如果使用“狮子吃番茄”等例子，重点应是“一个”，而不是“狮子吃很多食物”。

推荐分镜结构：

```text
具体角色/物品动作
  -> 数量或形状被强调
  -> 图像抽象成字形
  -> 汉字 + pinyin + 词语平静收束
```

## 节奏与语音同步（2026-05-03 追加）

2026-05-03 第二轮将“一”字样片改成 `2026-05-03-teaching-v2`：`7.8s` 横向教学舞台，使用“小兔找一找：一个苹果、一条小路、一根木棒，最后归纳成一横”的三例结构。用户反馈方向明显好很多，但仍有两个关键问题需要下一轮继续处理：

- 速度仍偏快。即使已经从 `4.8s` 拉到 `7.8s`，3-6 岁儿童仍需要更长观察和反应时间。下一轮不要急着进入下一例，每个例子应留出“出现 -> 指认/动作 -> 词语停留 -> 轻微重复”的完整节奏。
- 动画中的文字需要同步语音播读。视觉和听觉应同时工作：当画面出现“一个苹果”“一条小路”“一根木棒”“都是一”等文字时，应同步播放对应语音，而不是只靠静默字幕。

下一轮方向：

- 继续保留多例教学结构，但节奏应更像幼儿园老师带读：慢一点、停一下、重复一次重点。
- 给 HyperFrames composition 或旁路 metadata 增加可对齐的语音 cue，例如：

```js
voiceCues: [
  { at: 1.3, text: "一个苹果" },
  { at: 3.3, text: "一条小路" },
  { at: 5.2, text: "一根木棒" },
  { at: 6.9, text: "它们都有一个一" }
]
```

- 语音可以先用 H5/TTS 层按时间点播读，也可以在 HyperFrames 渲染阶段合成进视频。短期优先 H5 层播读，便于调节节奏和国际化；如果后续 CDN 视频要独立传播，再考虑把语音轨合进视频。
- 视觉文字不要密集堆叠。每次只出现一个核心短语，并让语音和角色动作同时指向这个短语。

### 2026-05-03 v4 语音规则修正

用户明确反馈：开头 `一，一个的一` 很快接 `一个苹果`，几乎没有停顿，听感糟糕。根因不是单个 cue 时间点，而是 H5 认字页存在两套语音：

- 页面进入后自动 `speakCurrent()`，读完整字音：`一，一个的一`。
- HyperFrames 视频播放后按 `voiceCues` 再读动画短语：`一个苹果` 等。

修正规则：

- 对存在 `recognitionVideo.voiceCues` 的字，进入认字页不要再自动读完整字音，避免和视频 cue 抢读。
- 点击认字舞台/喇叭时，如果当前字有视频 cue，默认重播视频和 cue，不先 `speakCurrent()`。
- 无视频 cue 的字继续保留原自动读字逻辑。
- 不要用大量碎 cue、怪标点、极慢 `rate` 或偏高 `pitch` 模拟停顿；浏览器 TTS 会更像 AI 拼接。
- cue 句子尽量完整自然，先使用 `一个苹果 / 一条小路 / 一根木棒 / 都是一` 这种短句，并用时间轴留停顿。
- 视频 cue 播放不应每句强制 `speechSynthesis.cancel()`；只有用户主动点读或切页时才打断。

短期仍可用浏览器 TTS 做验证；如果要进入正式儿童测试，应优先评估真人录音或离线生成稳定音频资产，再由 H5 或视频轨精确同步。

## 分阶段实施

### 2026-05-03 H5 营救后的新增硬门槛

本轮 review 发现，问题不只是“视频有没有接入”，而是 H5 页面没有把 HyperFrames 当作高质量教学媒介来承载：视频被压成横幅，其他字又回退到不稳定静态素材，导致第一字和后续 19 字之间出现明显断层。

因此从本轮开始，HyperFrames 视频进入 H5 前必须同时满足产品门槛和页面门槛：

#### 视频质量门槛

- **2 秒内出现教学钩子**：孩子必须很快看见“这个字为什么这样认/这样写”的核心线索。
- **汉字永远是焦点**：角色、动物、场景只能辅助字形记忆，不能变成独立剧情。
- **语音和画面同拍**：每个 `voiceCue` 至少有约 1.6 秒视觉停留，不再用碎句、怪停顿、快切来凑节奏。
- **最终帧可独立成立**：final frame 必须能作为 poster/fallback，平静、清楚、无功能 UI。
- **禁止 App 壳进入视频**：视频内不放顶部导航、下一步按钮、奖励爆炸、密集字幕；这些属于 H5 页面。

#### H5 承载门槛

- P03 认字页把视频舞台作为第一视觉，不再把视频当成普通插图小卡片。
- 有 HyperFrames 视频的字：使用 `poster -> video -> final frame` 的稳定退路，TTS 只跟随 `voiceCues`，不再抢读完整字音。
- 无 HyperFrames 视频的字：先使用 H5 原生字形舞台（基于笔画数据绘制），避免把棋盘格、长图 overlay、错位旧素材直接暴露给孩子。
- 组词、大字、拼音仍由 H5 承担，作为动画后的确认和复述区；视频不重复整页信息架构。

#### 下一批样片优先级

先做 5 个能覆盖范式的样片，而不是一次铺满 20 个：

| 优先级 | 字 | 教学钩子 | 建议时长 |
|---|---|---|---|
| P0 | 二 | 两条平平线 | 约 7.2s |
| P0 | 三 | 三条线按节奏排好 | 约 7.6s |
| P0 | 人 | 两笔靠一靠，站起来 | 约 7.8s |
| P1 | 山 | 三座山峰长出来 | 约 7.8s |
| P1 | 火 | 火苗动作对应点撇结构 | 约 8.0s |

## 验收标准

- 孩子视角：进入 P03 后 5 秒内能被画面吸引，并看见一个清楚的字形动作。
- 教学视角：动画结束后，画面能回答“这个字为什么这样写/这样认”。
- 产品视角：视频不破坏现有认 -> 写 -> 练流程，不增加等待焦虑。
- 技术视角：H5 在无视频、视频加载失败、reduced-motion 下都能正常学习。
- 视觉视角：仍保持田园暖彩和晒暖绘本感，不回到紫蓝梦幻、霓虹、强粒子。
